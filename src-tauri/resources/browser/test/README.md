# Проверка браузерного runtime

Используйте отдельный подготовленный runtime и временные профили. Файлы владельца,
его Chrome, login и модели не используются. Точные аргументы каждого сценария
указаны в заголовке соответствующего `.mjs`; не подменяйте путь рабочим профилем.

- `proxy.mjs` проверяет настоящий MCP SDK/proxy через собственный HTTP gateway.
- `smoke.mjs` проверяет Chromium, snapshot, формы, загрузки в разрешённых корнях,
  кадры, ручной ввод, auth/Origin и восстановление после рестарта.
- `recovery.mjs` проверяет отдельные очереди, композиции действий, deadlines,
  отмену, неопределённый результат и отсутствие повторов ввода.
- Остальные `*.test.mjs` покрывают контракты модулей; запускайте относящиеся к
  изменению проверки, а не все живые браузеры одновременно.

Пример с заранее подготовленным тестовым runtime:

```sh
node src-tauri/resources/browser/test/proxy.mjs /absolute/test-runtime/current
node src-tauri/resources/browser/test/smoke.mjs /absolute/test-runtime
```

Успех transport/unit-сценария не доказывает установку или GUI на другой ОС.
Сохраняйте версию браузера, commit и результат конкретного сценария в приватном
receipt. [Профили](../../../../docs/BROWSER-PREFERENCES.md),
[браузер](../../../../docs/BROWSER.md), [приёмка](../../../../docs/PLATFORM-ACCEPTANCE.md).
