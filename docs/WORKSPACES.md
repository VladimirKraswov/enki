# Новый чат, проекты и компьютеры

Выбор проекта не является условием начала работы. **Новый чат / ⌘N** открывает чистый экран. В центре — «Выбрать проект» с поиском и вариантом «Работать без проекта». Под полем сообщения — место выполнения: этот компьютер или сохранённое SSH-подключение. Модель, усилие, доступ, контекст, очередь и диктовка работают в обоих режимах.

## Без проекта

Подходит для вопросов, поиска, анализа, настройки Mac или серверов. Набор инструментов — это инструменты встроенного Enki Runtime (закреплённый Pi SDK) плюс явно подключённые общие MCP, браузер и навыки; оболочка не добавляет модели веб-поиск, если такой инструмент не подключён.

Первое сообщение или открытие терминала создаёт отдельный каталог `~/.local/share/enki/chats/<UUID>` на **машине выполнения**. Не создаётся Git-репозиторий и не требуется вручную выбирать папку. Рабочие файлы разных новых чатов разделены. Эти каталоги не появляются в списке проектов.

Сам каталог не является файловой песочницей: агент может работать с другими путями в пределах выбранного режима доступа и разрешений ОС. «Без проекта» не означает ограничение только обычным текстовым ответом. Разрешения — политика доступа Enki Runtime для этой сессии; приложение не подменяет системные ограничения и не выдаёт права администратора.

Чаты видны отдельно в боковой панели. Открытие чата восстанавливает его реальный рабочий каталог и историю Enki Runtime. Приложение хранит локальный индекс названий/ID/каталогов для навигации; сообщения и авторитетное состояние принадлежат ядру. При открытии каталог синхронизируется с API ядра. Удаление истории не удаляет созданные файлы. Архивирование обратимо. Старые истории OpenCode/Pi CLI доступны только для чтения и продолжаются в Enki явно.

## Проект

Можно выбрать существующий проект или открыть папку. Папка без Git также допустима. Выбор папки на экране нового чата не открывает автоматически предыдущую сессию этого проекта. Переход к проекту из боковой панели может восстановить последний выбранный диалог. Добавленные вручную папки сохраняются отдельно для каждого компьютера.

## На этом компьютере

Используется встроенный Enki Runtime, который запускает и контролирует само приложение (loopback, ключ доступа не покидает компьютер); отдельный сервер OpenCode не нужен и не запускается. Модель при этом может обслуживаться на GPU-сервере: **место модели и место выполнения инструментов — разные вещи**. В этом режиме терминал и операции с файлами выполняются на этом компьютере.

Настройка удалённой машины из локального чата тоже допустима: можно поручить агенту воспользоваться существующим `ssh` в рамках разрешений сессии. Для переноса самого окружения агента, файлов и терминала на сервер используйте SSH-режим ниже.

## Работать удалённо

1. В меню места выполнения выберите «Работать удалённо…» или откройте «Удалённые компьютеры» в настройках.
2. Введите существующий SSH-алиас из `~/.ssh/config` либо `user@host` и понятное имя. Нестандартный SSH-порт/ProxyJump/IdentityFile задаются в стандартном SSH-конфиге; порт API вводить не нужно.
3. На хосте (Linux x64) должно быть установлено Enki Runtime той же версии контракта — операторская процедура описана в [REMOTE-RUNTIME.md](REMOTE-RUNTIME.md). Внешний OpenCode или Pi CLI на хосте не нужен и не используется.
4. Enki выполняет на хосте фиксированную команду `enki-runtime ensure`, получает loopback-порт и ключ доступа (только в памяти) и открывает строгий SSH-туннель; через туннель должен ответить тот же экземпляр ядра. Пароля API нет.
5. После подключения выберите проект **этого сервера** или работайте без проекта. «Открыть папку на сервере» принимает абсолютный серверный путь, не запускает диалог выбора папки этого компьютера.

Приложение управляет только собственным SSH-туннелем и командой `ensure` ядра Enki; чужие службы на хосте оно не устанавливает, не запускает и не завершает. API остаётся на loopback; CSP WebView не расширена до произвольной сети. Используются системный SSH, обычные ключи, `BatchMode=yes`, `StrictHostKeyChecking=yes`, timeout и keepalive. Первичное принятие ключа или интерактивную SSH-аутентификацию выполните обычным `ssh` в терминале. Пароли SSH приложение не запрашивает и не хранит.

При недоступном сервере UI сообщает конкретную ошибку и не перенаправляет задачу на Mac. При возврате на локальную машину восстанавливаются её собственные проекты, черновики и PTY. Смена компьютера переключает представление; уже запущенная удалённая задача не переносится и не прерывается.

## Изоляция и восстановление

- Серверные ID, папки, проекты, выбор модели, черновики, очереди, PTY и индекс чатов разделены по стабильной идентичности сервера. У SSH это адрес и удалённый порт; новый локальный порт туннеля после перезапуска не создаёт другую историю.
- Смена компьютера/папки инвалидирует старые HTTP/SSE-ответы. Новое SSH-подключение, завершившееся после возврата пользователя на Mac, не перехватывает интерфейс.
- Двойной Enter во время подготовки каталога не создаёт два запроса. Ошибка создания каталога оставляет черновик; запуска в случайной домашней папке нет.
- Автосжатие контекста выполняет Pi SDK внутри Enki Runtime; Enki не добавляет своё. Индикатор показывает данные выбранной модели и текущей сессии, включая чаты без проекта.
- SSH-туннели закрываются при выходе из Enki. Удалённое ядро на хосте продолжает работать и выполнять свои очереди. Ключи доступа не входят в localStorage, URL, Git или diagnostic receipts.

## Границы

Проверяемый сценарий: macOS/Windows/Linux-клиент и Linux x64 SSH-хост с установленным Enki Runtime. Облачный вычислительный сервис Codex, Git worktree и перемещение уже существующей сессии между машинами здесь не реализованы. Доступ без проекта не обещает системный sandbox или идентичные Codex инструменты.

Сценарий взят из требований владельца и [официального описания чатов без выбора папки в Codex](https://learn.chatgpt.com/docs/changelog): проект необязателен, задачи могут быть исследовательскими и инструментальными. Закрытый UI Codex не копируется из исходников; в этой версии реализуются перечисленные пользовательские действия, а не заявляется совпадение всех функций продукта.

## Боковая панель

Нажатие на проект раскрывает его сессии, не переключая текущий чат. Несколько проектов можно раскрыть одновременно. Раскрытые и свёрнутые группы запоминаются отдельно для каждого сервера. Закреплённые папки остаются первыми; выбор сессии не переставляет группы. Кнопка «+» справа от проекта начинает новый чат в этой папке.

«Недавние» находятся под проектами и объединяют последние сессии текущего сервера, включая работу без проекта. Архив рядом относится ко всем проектам; восстановление возвращает сессию в её исходную папку. Длинные списки догружаются через «Ещё сессии» / «Показать ещё». Ошибка загрузки отдельного проекта не закрывает текущий чат и допускает повтор.
