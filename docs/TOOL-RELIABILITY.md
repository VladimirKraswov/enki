# Надёжная работа инструментов

Enki использует инструменты и агентский цикл Pi SDK; приложение добавляет
проверяемые границы доступа, транспорт, журналирование и наблюдаемый статус.
Инструкция модели помогает выбору действий, но не заменяет эти проверки.

- Перед правкой читать текущий участок и использовать однозначный контекст.
  `safe_edit` сохраняет проверку hash/совпадения; после конфликта перечитать файл,
  а не отключать guard. [Инструменты проекта](PROJECT-TOOLS.md).
- Перед браузерным действием получить актуальное наблюдение. Смена страницы,
  viewport или ручной ввод делают координаты устаревшими; отклонённый клик
  не повторяется автоматически. [Браузер](BROWSER.md).
- Для компьютерных действий использовать явную живую сессию и точное окно.
  Закрытая сессия не возрождается от клика. [Управление компьютером](COMPUTER-USE.md).
- Долгая команда должна иметь конечный срок, ограниченный вывод и понятный статус.
  Отсутствие нового текста не доказывает зависание. Завершать только своё дерево
  процессов; неизвестная очистка не считается простоем.
- Сетевой retry допустим для чтения и доказуемо неотправленной операции, с пределом
  попыток и backoff. Если результат мутации неизвестен, сначала сверить квитанцию.
- Ошибка модели, лимит вывода, Stop, ожидаемый ответ и завершение — разные исходы.
  Не выдавать пустой ответ или обрыв на tool-call за успешную работу.
- Автопродолжение выполняется только по явно заданному ограниченному контракту
  [Agent Factory](AGENT-FACTORY.md) или таймеру, а не бесконечным «продолжай».

Проверяйте общий класс сбоя регрессией на изолированных данных. После двух
неудачных попыток собирайте новые факты. Не ослабляйте разрешения, TLS, checksum
или assertions ради зелёного результата. Проверки [выпуска](VERIFICATION.md)
дополняют профильные сценарии, но не обещают отсутствие будущих ошибок модели.
