# Проекты и передача задач (0.2.3)

## Убрать проект

В строке проекта откройте «…» → «Убрать проект из списка». После подтверждения папка и её сессии перестанут показываться в проектах и недавних. Файлы, история чатов, черновики и выполняющиеся задачи сохраняются. «Убранные проекты» возвращает папку в панель; повторное добавление той же папки также восстанавливает её. Список убранных проектов разделён по серверам.

## Передать задачу

Нажмите **Передать** в заголовке чата или **Передать задание…** в меню сессии.

1. Выберите компьютер, проект и сессию-получателя. Поиск работает по названию сессии на сервере, а не только по видимым недавним. Длинные списки догружаются. Чаты без проекта и убранные проекты также доступны для явного выбора.
2. Напишите, что получатель должен сделать.
3. Нажмите **Собрать важный контекст**. Агент получает копию доступной истории исходной задачи, включая её сохранённые сводки. В отдельной служебной сессии с запрещёнными инструментами он готовит пакет: цель, решения, актуальные ограничения, прогресс, файлы/коммиты/команды, машины и способы доступа, результаты проверок, незавершённая работа и следующий шаг. Это не простое копирование последнего сообщения. Исходная сессия не изменяется. Копия архивируется после подготовки; отмена останавливает только её.
4. Проверьте и при необходимости отредактируйте пакет. Можно составить его вручную. Реальное качество сводки зависит от модели и сохранившегося контекста; отсутствующие в истории сведения не восстанавливаются автоматически. Пароли и токены агенту предписано заменять ссылками на доступное хранилище/ключи; передаваемый текст виден целиком.
5. **Отправить и начать** добавляет поручение в существующую сессию. Она сохраняет свой проект, модель, агента и разрешения. **Сохранить черновик** добавляет текст к её существующему черновику и не запускает модель. Последний вариант подходит, если получатель занят или ожидает ответа на вопрос/разрешение.

При потере подтверждения приложение проверяет сообщение по ID. Если результат нельзя подтвердить, оно сообщает неопределённый статус и предлагает открыть получателя; автоматической повторной отправки нет. Принятое поручение ещё не означает завершённую работу — результат появляется в целевой сессии.

Для другого компьютера заранее настройте SSH-подключение (ядро Enki на том хосте, [удалённый хост](REMOTE-RUNTIME.md)). Передача использует отдельный клиент и его учётные данные; просмотр списка на другом компьютере не переключает текущий чат. Подключение может потребовать пароль, уже заданный через обычный диалог подключения. Если обе сессии работают с разными машинами через SSH-инструменты одного ядра (как перенесённые инфраструктурные чаты), выбирайте их на текущем компьютере: их окружения описаны в собственных контекстах.

Подготовка пакета не запускается параллельно с другой задачей на сервере источника. Дождитесь завершения или подготовьте контекст вручную. Передача выполняется явным выбором в UI; отдельный инструмент автоматического поиска/делегирования для модели в этой версии не устанавливается. Автоматического обмена секретами, переноса файлов между машинами и синхронизации переписок нет.
