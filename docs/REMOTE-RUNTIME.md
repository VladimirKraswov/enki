# Удалённый хост: Enki Runtime по SSH

Удалённый проект выполняется собственным Enki Runtime на Linux x64 хосте — тем же
закреплённым Pi SDK и Node, что встроены в приложение. Внешние OpenCode/Pi на
хосте не нужны и не используются. Если удалённое подключение не удалось, работа
никогда не переносится на этот компьютер.

## Как Enki подключается

1. Enki выполняет по SSH (`BatchMode=yes`, `StrictHostKeyChecking=yes`, только
   алиас или `user@host`) фиксированную команду
   `"$HOME/.local/share/enki/runtime-dist/current/bin/enki-runtime" ensure`.
   Ничего, введённого пользователем, в удалённую команду не подставляется.
2. `ensure` запускает (или находит уже работающий) демон ядра с данными в
   `~/.local/share/enki/runtime` и печатает одну строку JSON: порт на обратной
   петле, ключ доступа, экземпляр и версию контракта. Несовпадение контракта —
   ошибка с просьбой обновить ядро на хосте.
3. Enki открывает SSH-туннель `-L` на свой loopback-порт и проверяет
   аутентифицированный `/v1/health` того же экземпляра. Ключ хранится только в
   памяти и никогда не попадает в URL или журнал.

Ключ хоста должен уже быть в `known_hosts`; Enki не принимает новые ключи сам.

## Установка и обновление ядра на хосте (операторская процедура)

Встроенного установщика в приложении пока нет: ядро на хост ставит оператор
доверенным журналируемым установщиком. Запускается он всегда через точку входа
`scripts/runtime/install-remote-entry.mjs`: она сначала проверяет Node.js хоста
и только потом загружает сам установщик `install-remote.mjs` (SQLite и прочие
модули), так что неподходящий Node отказывает до любого изменения.

1. На машине сборки из проверенного исходника:
   `npm run runtime:prepare -- --platform linux-x64 --remote-tarball`.
   Результат: `src-tauri/target/enki-agent/dist/enki-runtime-linux-x64-<version>.tar.gz`.
   SHA256 манифеста — поле `manifestSha256` в
   `src-tauri/target/enki-agent/preparation-receipt.json` этой же сборки.
   Именно это значение аутентифицирует пакет; файл `.sha256` рядом с архивом
   защищает только от повреждения при копировании и аутентификацией не является.
2. Скопируйте архив на хост и распакуйте во временный каталог (получится
   каталог `artifact/`). Скопируйте рядом весь доверенный каталог
   `scripts/runtime/` из того же исходника (установщик импортирует
   `artifact.mjs`, `native-port.mjs`, `build-runner.mjs`, `sdk-contract.mjs`,
   `host-node.mjs`) и запускайте из него.
3. На хосте нужен доверенный Node.js 22.13+ (проверенный — 24.22.1) только для
   запуска установщика; само ядро использует свой закреплённый Node из пакета.
   На неподдерживаемом Node установщик сразу отказывается и ничего не меняет.

```sh
node scripts/runtime/install-remote-entry.mjs \
  --dist "$HOME/.local/share/enki/runtime-dist" \
  --data "$HOME/.local/share/enki/runtime" \
  --artifact /tmp/enki-runtime/artifact \
  --manifest-sha256 <manifestSha256 из receipt сборки>
```

Установщик до любого импорта кода пакета сверяет каждый файл с манифестом,
публикует неизменяемую копию под OS-блокировкой, принимает только
`qualified` пары SDK/Node из `sdk-contract.mjs`, перед заменой делает парную
резервную копию базы и транскриптов работающего ядра и ведёт журнал: прерванное
обновление восстанавливается при следующем запуске, потерянное подтверждение
сверяется запросом по точному id, а не повтором.

Откат: тот же вызов `install-remote-entry.mjs` с `--rollback`; смена SDK или схемы данных дополнительно
требует `--restore-paired-data` (восстановление парной копии; новые данные
сохраняются в отдельном каталоге, ничего не удаляется). Подробнее о версиях —
[SDK-UPGRADE.md](SDK-UPGRADE.md).

## Ограничения

* Поддерживается только Linux x64 хост. Windows/macOS как удалённые хосты не
  поддерживаются.
* Установка/обновление на хосте — ручная операторская процедура; Enki сам ядро
  на хост не ставит.
* Живая проверка этой процедуры на реальном хосте для 2.0 ещё должна быть
  выполнена и отражена в [VERIFICATION.md](VERIFICATION.md).
