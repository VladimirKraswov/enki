# Управление компьютером

Enki подключает отдельный подписанный **Cua Driver 0.28.2** через локальный MCP. Драйвер работает с нативными окнами macOS (и Windows через UI Automation), деревом доступности, снимками и отдельным визуальным курсором агента. Вычисления выполняет модель, выбранная в чате Enki; отдельный облачный компьютер или ключ Cua не требуется.

## Включение

1. Установите официальный Cua Driver в `/Applications/CuaDriver.app` из [релиза](https://github.com/trycua/cua/releases/tag/cua-driver-rs-v0.28.2). На машине владельца он установлен из проверенного архива с подписью **Cua AI, Inc. / YCK386LBJ7**, bundle `com.trycua.driver`, notarization ticket.
2. В Enki выберите «Этот компьютер», откройте **Настройки → Управление компьютером → Разрешения macOS…**. Cua Driver запросит Accessibility и Screen Recording. Эти разрешения выдаёт пользователь в macOS; агент их не переключает. На новых macOS может потребоваться отдельное подтверждение прямого захвата окна.
3. Нажмите **Подключить**. Enki проверяет и при необходимости обновляет мост MCP, включает локальный выключатель, записывает собственный навык и добавляет в общий реестр зарезервированную MCP-запись `cua-desktop` (собственная программа Enki с `--computer-mcp`; чужая запись с тем же идентификатором не заменяется). Текущий свободный чат открывается с обновлёнными инструментами `mesh_cua_desktop_*` без отправки запроса модели. Успех показывается только после регистрации инструментов в этом чате: **Подключено · 22 инструмента** (количество зависит от версии драйвера). Остальные чаты получают изменения при следующем обращении; работа агента не прерывается и запросы не повторяются. Создавать новый чат не нужно. Кнопка **Проверить** перечитывает состояние драйвера и настроек, не запускает задачи.
4. В обычном чате попросите выполнить конкретную задачу в конкретном приложении. Действия видны как вызовы инструментов, а поверх управляемого окна появляется курсор агента. Снимки и текст интерфейса получает выбранная модель — учитывайте это при выборе локальной или облачной модели.

Навык устанавливается в `~/.local/share/enki/computer/skill/SKILL.md` (в отдельном профиле — внутри профиля). Ядро загружает его только пока управление включено на этом компьютере, драйвер установлен, а навык — обычный файл без ссылок.

## Контроль

- **Выключить** закрывает общий шлюз Enki: последующие вызовы блокируются даже в ранее открытых чатах. Запись реестра сохраняется с `enabled:false`.
- **Остановить управление Mac** дополнительно отзывает все текущие сеансы Cua Driver на этом Mac. Эта кнопка доступна и во время работы агента; она затрагивает все приложения, использующие тот же сервис Cua.
- Обычная кнопка «Стоп» в чате останавливает ход агента. Она не заменяет отзыв активного управления драйвером.
- Включение, выключение и действия драйвера (`computer_set_enabled`, `computer_action`) принимаются только от главного окна Enki; команды драйвера ограничены по времени и выводу.
- Шлюз предоставляет только инструменты наблюдения и фоновой работы с конкретным окном. Инструменты принудительного завершения приложений, изменения конфигурации драйвера, записи экрана и управления полным рабочим столом не выдаются модели. Permission-check через MCP всегда выполняется без системных запросов доступа.
- Окно должно находиться на текущем рабочем столе (Space) macOS. Окно на другом Space может быть видно на снимке, но драйвер отказывает во вводе с `off_space_or_ax_unresolved`. Перенесите/откройте его на текущем рабочем столе. Фоновые действия не гарантированы для каждого контрола/приложения. При `background_unavailable` агент должен сообщить ограничение; шлюз не переключает управление на физическую мышь. Это не обещание полного совпадения с Codex.
- Интеграция относится к компьютеру, где работает ядро Enki и установлен драйвер. При выбранном SSH-хосте локальные действия заблокированы: удалённое ядро не получает управление этим компьютером. Подключения браузерных профилей, отдельная DOM-интеграция и удалённый рабочий стол не добавлены.

## Устройство

Общий MCP-пул ядра Enki запускает программу Enki с `--computer-mcp`. Этот режим не создаёт окно приложения: он проксирует MCP stdio к официальному драйверу, фильтрует набор инструментов и проверяет локальный выключатель перед каждым вызовом. Изображения сохраняются; у инструментов действий цель упрощена до обязательных PID и ID окна. Структурированные результаты дополнительно включаются текстовым JSON-блоком, чтобы модель видела PID, ID окон и токены элементов (в истории чата сохраняется ограниченная сводка, а снимки — только в самом ответе инструмента). Целевые PID/окна берутся из свежего наблюдения. Драйвер сохраняет собственную macOS identity и разрешения при обновлениях Enki. Телеметрия драйвера в этой установке отключена; история действий/запись экрана не включены.

Основа и ограничения: [Cua Driver](https://github.com/trycua/cua/blob/main/libs/cua-driver/README.md), [контракт фоновых действий](https://github.com/trycua/cua/blob/main/docs/content/docs/reference/cua-driver/contracts.mdx). Драйвер обновляется независимо от Enki; проверена указанная версия, совместимость будущих версий требует проверки.

Экстренная остановка отзывает runtime драйвера. Следующее явное нажатие «Подключить» закрывает только такой отозванный runtime и создаёт новый с обычной политикой. Вызовы модели не могут перезапускать драйвер; другие отказы доступа не обходятся. Готовность проверяется по разрешениям драйвера, а не только по MCP-соединению.

## Явная сессия и восстановление

Агент явно создаёт свою Cua-сессию и передаёт возвращённый `session` каждому
вызову, включая список окон. Последняя созданная сессия не становится
неявной сессией MCP: потеря имени приводила к повторным `session has ended`.
Шлюз теперь проверяет это до отправки драйверу. Закрытые сессии не
возрождаются автоматически. После перезапуска приложения PID/ID окна и
координаты нужно получить заново. Скриншот обычно доступен прямо в результате;
сохранение в файл необязательно. [Разбор и проверки](TOOL-RELIABILITY.md).
