# Удалённое управление через LAN Hub

`https://192.168.31.223:8443/remote` — мобильная и настольная страница для
управления подключёнными к Hub компьютерами владельца. По явному поручению
владельца в локальной сети **нет входа, регистрации, паролей и токенов**.
Слушатель Hub по-прежнему принимает только loopback и `192.168.31.0/24`; WAN-
проброс не добавляется. Это не публичный/мультипользовательский режим.

Hub не выполняет модельные запросы, команды ОС или агентский цикл. Каждый Enki
Runtime периодически передаёт ограниченный снимок устройства, получает команды
и выполняет их через существующие dispatcher, очередь, вопросы и разрешения.
История и рабочие файлы остаются на компьютере. Повтор доставленной команды в
текущем Runtime возвращает сохранённый результат; ID команды предотвращает
дубликат нового задания. Перезапуск Runtime заново синхронизирует состояние.

Страница поддерживает:

- устройства, их действительную свежесть связи и версии;
- проекты и сессии, статусы, последние 100 сообщений и ход инструментов;
- новый проектный чат с первым заданием, промпт/уточнение, очередь и остановку;
- ответы на вопросы и запросы разрешений;
- выбор модели и ручное сжатие контекста через Runtime;
- режим доступа по умолчанию, автосжатие, browser/LSP и обновление каталога;
- консоль Hub (`/console`) с релизами, устройствами и сервисами моделей;
- обновление Enki на любом подключённом устройстве: проверка, скачивание/сборка,
  установка через существующий подписанный updater после авторитетного простоя
  агентов. Удалённый apply не заменяет файлы напрямую и не обходит backup.

## PWA

`/remote` — устанавливаемый PWA с manifest, иконками и service worker. Android и
desktop используют системное «Установить приложение»; iPhone/iPad — Safari
«Поделиться → На экран “Домой”». Запуск происходит в standalone-окне.
Service worker кэширует только статическую оболочку, никогда не кэширует API,
чаты, команды или аудио. Офлайн доступен лишь shell с честным «Нет связи с Hub»;
Runtime и Hub остаются источниками данных при восстановлении сети. Для PWA и
микрофона самоподписанный Hub certificate должен быть доверен ОС: обход browser
warning не включает service worker. Кнопка ⬇ диагностирует это и предлагает
`/remote-certificate.crt` (только public certificate) с SHA-256 для сверки.

## Архитектура синхронизации

Runtime `remote/snapshot.ts` строит read-only overview/detail, `remote/sync.ts`
владеет reconnect/backoff и одним атомарным sync request, `remote.ts` выполняет
typed commands через существующие Runtime interfaces. Browser `remote-sync.js`
является единственным scheduler: отменяет stale request при выборе, не запускает
overlap и останавливается в скрытой вкладке.

Hub в одной SQLite transaction сохраняет overview+watched detail и монотонные
revision/detailRevision. Heartbeat без изменений обновляет freshness, но не
revision. Browser long-poll `overview?device=…&since=…` спит до20с и просыпается
при новой ревизии; detail revision позволяет не скачивать неизменённую историю.
Это выбрано вместо дополнительного WebSocket stack: сохраняется существующий
pinned HTTPS и LAN boundary, нет нового порта или протокола команд. Изменение
доставляется push-подобно, а после обрыва обычный HTTP запрос восстанавливается.
Статус необязательного updater-а загружается в фоне и никогда не задерживает
session sync. Watchdog 30с fencing-поколением заменяет зависший bridge call живым
циклом; отдельный backoff ограничен. Выбранная история запрашивается до overview
long-poll, поэтому первый экран не ждёт 20с. Неизменённая история кэшируется по
updated сессии; live queue/status читаются каждый цикл.

Hub не выдаёт detail старше30с как живой: сообщения остаются явно помеченным
последним снимком, но queue, вопросы, permissions и status очищаются. В UI
устройство без heartbeat называется «нет связи», а не «офлайн»; старая очередь и
фраза «снимок устарел» больше не показываются.
Runtime sync каждую1с, transient backoff до10с, изменение watch/команда вызывает
следующий snapshot немедленно.

Remote detail ограничен 1.2МиБ до отправки (whole HTTP body Hub 2МиБ): текст/
вывод сокращаются с явной пометкой, сохраняются последние сообщения, а live
queue/status/questions никогда не выбрасываются. Ошибка чтения истории даёт
warning, но не блокирует live-снимок. Полная локальная история не изменяется.
Browser отмечает queue snapshot старше20с как устаревший, не выдавая его за
подтверждённое текущее состояние.

## Диктовка

Кнопка «Надиктовать» запрашивает микрофон только после нажатия. MediaRecorder
отправляет одну запись (до 25 МиБ) на `/api/remote/asr`; Hub передаёт её в
существующий GigaAM ASR на CT201 и возвращает только распознанный текст. Текст
вставляется в локальный черновик страницы и **не отправляет задание сам**.
Запись в Hub не сохраняется. Для микрофона на телефоне нужен HTTPS и разрешение
браузера; при первом открытии частного сертификата его нужно явно доверить в
браузере/ОС после проверки отпечатка.

Проверки: `python3 -m unittest discover -s services/hub/tests`, Runtime
integration `remote-control.test.ts`, браузерный сценарий страницы. Живая
проверка каждой ОС и реального микрофона телефона — отдельная приёмка, не
заменяется модульными тестами.
