# Контекст, кэш и ход запроса

Enki различает подготовку модели на Hub, ожидание сервера, обработку входного
контекста, размышление модели и формирование ответа. Выполнение инструмента
показывается отдельно. Отсутствие текста само по себе не означает зависание:
длинная история может обрабатываться до начала генерации.

## Прогресс

Строка состояния относится к конкретным компьютеру, чату и запросу. Если движок
отдаёт счётчики, Enki показывает обработанные токены, общий размер и часть,
повторно использованную из кэша. Обработанное количество включает кэшированные
токены. Полоска не заполняется по таймеру и не изображает готовность ответа.
Время ожидания продолжает обновляться и при отсутствии новых данных сервера.

Если протокол не предоставляет счётчиков, показывается ожидание без процентов.
Первые дельты SDK меняют фазу на размышление или ответ. При сжатии истории это
явно указано в строке. После отмены или завершения прогресс не переносится на
следующий запрос. После переподключения актуальный статус берётся из снимка
Runtime; при потере связи интерфейс не выдаёт старый прогресс за подтверждённый.

Hub объявляет поддержку NInfer отдельно для каждого целевого backend через
`promptProgress: "prompt-progress-v1"`. Только для такого маршрута Enki добавляет
`return_progress: true` и читает `prompt_progress` из SSE Chat Completions.
Неизвестные возможности не включаются по названию модели или провайдера.
SDK получает исходные байты ответа, включая ошибки, usage и вызовы инструментов.
Прогресс ограничен по частоте, заменяется в памяти журнала и не записывает
каждую порцию токенов в SQLite.

## Кэш вычислений

KV/prefix cache хранит результат обработки совпадающего начала запроса на
сервере модели. Его наличие не уменьшает историю диалога. Модель могла быть
выгружена; сервер также может освободить кэш под другую работу. Даже неизменная
история не гарантирует попадание в кэш.

Для устойчивого префикса Enki завершает ограниченное подключение браузерных
инструментов до того, как SDK фиксирует системный промпт и проверяет бюджет.
Параллельное обнаружение MCP не должно случайно менять порядок объявления
инструментов: объявления NInfer канонизируются по имени и ключам схемы.
Пользовательские сообщения, содержание инструкций и порядок истории не меняются.
Изменения инструкций и набора инструментов применяются честно: старый кэш не
считается подходящим только ради ускорения.

## Сжатие истории

Автосжатие выполняет штатный Pi SDK между шагами. Изменение переключателя и
бюджетов применяется к уже открытым сессиям, включая следующие шаги активного
агента: пересоздание чата не требуется. Это создание выжимки рабочего
контекста; исходная переписка остаётся доступной. Оно не является очисткой кэша.

Единый расчёт SDK и индикатора резервирует объявленный объём ответа модели и
4096 токенов запаса, используемые закреплённым SDK при ограничении вывода.
Явно заданный больший резерв сохраняется. Порог и сохраняемый хвост зависят от
окна модели; хвост не может занимать всё доступное место маленькой модели.
Для окна 262144 и ответа 32768 порог составляет 225280 токенов — около 86%.
Размер окна, веса, квантование и настройки генерации от этого не меняются.

Перед отправкой нового пользовательского запроса Runtime дополнительно проверяет
историю, инструкции, инструменты и вложения. Если они не помещаются, он сжимает
историю текущей моделью и проверяет результат до перехода на другую. Несжимаемый
слишком большой новый запрос возвращается с объяснением; история не обрезается
молча. «Сжать сейчас» доступно после завершения ответа агента.

## Выбор модели

Сохранённая модель чата и её текущая доступность — разные данные. Временный сбой
каталога, авторизации или сети не стирает название и не подменяет его моделью
по умолчанию. Недоступность показывается отдельно. Наличие сохранённого выбора
не разрешает inference: ключ, маршрут, контекст и готовность проверяются Runtime
перед выполнением запроса. Список новых вариантов по-прежнему скрывает
подтверждённо недоступные модели.
