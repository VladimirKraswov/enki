# Images and materials in Enki

Settings → **Изображения**: enabled switch, provider, base API URL, model, OS-vault API key and read-only connection check. Each field has a help modal. Source defaults contain only the LAN endpoint/model, no secret. Local operator provisioning can place a private0600 `image-api.bootstrap` beside `image-generation.json`; installed Enki imports it into its own OS vault on first use and removes the temporary file. Existing keys are preserved. This is not a release credential and must never enter Git/Hub packets.

The owner device is provisioned for CPU Inference. Other devices set their own API/key; arbitrary HTTPS or private-LAN HTTP APIs are supported. `Enki CPU` offers jobs, progress, cancellation, icon/material bundles. `OpenAI-compatible` uses base`/v1`, `/images/generations`, n1 and b64_json PNG response; default image size1024 for quality (explicit LCM draft512). Use the dimensions actually supported by that provider. Vendor-specific APIs may need an adapter; the generic adapter never fetches untrusted response URLs. Material/icon bundle helpers require the Enki provider; other APIs may be used one image at a time.

Shared MCP **enki-images / «Генерация изображений»**, OpenCode and Pi:

- `image_inputs`: list this session’s attached originals, previous original and last generated result;
- `edit_image`: actual image-to-image redraw from `attachment:N` or `latest`;
- `generate_image`: start drawing;
- `generate_icon_pack`:1–8 subjects with shared style, palette and background;
- `generate_material`: texture + aligned normal/height/roughness/metallic and opposite lighting previews;
- `image_status`: readiness/progress, bounded20s wait;
- `get_images`: retrieve ready/partial results; `include_vision=true` only if the current model supports image input;
- `cancel_image`: cancel without deleting finished files.

The model should call these tools for raster-generation requests, retrieve and show the actual output, and visually inspect it when capable. A returned text description is not an image. Tool descriptions require honest review and bound corrective generations. No separate autonomous agent loop or regex intent interceptor is added. Non-Vision models get file references/previews without incompatible image-input blocks by default; Vision gets actual PNG blocks when requested. Never claim visual review without seeing those pixels.

Results are saved without overwriting files in the agent workspace `.enki/generated-images/<job>/`: PNG,256px previews, ZIP, manifest. Permission/cancellation remain with the selected engine. Keys are injected privately into the tool process, never into prompts. Key changes take effect on reconnection; existing work is not aborted to change settings. Use the API that created an old job to retrieve it.

Generated cards remain visible when “Ход работы” is collapsed; duplicate retrievals do not duplicate images. Only visible/nearby thumbnails load; full PNGs load on click into the existing viewer. PNG dimensions/bytes and generated-file paths are bounded. When an agent's file is on another device, Enki may fetch the exact job/file from its configured authenticated Enki API, never from a tool-supplied remote URL. Remote retrieval requires that device's API configuration and the service's retained result.

Quality: use model `enki-image-auto` (visually qualified SDXL for new art/materials and FLUX.2 Klein4B for image edits), or select `sdxl-lightning` explicitly. `lcm-dreamshaper-v7` is an explicit fast draft; existing custom model/API choices are preserved. Upgrade109 migrates only the former factory LCM+LAN endpoint to quality, saves `image-generation.before-quality-v1.json`, and records a one-time marker; explicitly choosing LCM afterwards is respected. Keep anime2D unless3D was requested; do not add haze/bokeh by default. First model/periodic-mode loading is reported through job status.

Materials: ask “Создай текстуру камня с normal map, высотой и roughness; OpenGL, рельеф6, покажи под боковым светом.” Tileable materials use circular convolutions during denoising AND VAE decoding, not border crossfades that painted bands into the previous output. Brick/granite use explicitly reported procedural PBR recipes with authored aligned height; use material.surface=image to force neural generation instead. Other image-based surfaces approximate height from albedo. Roughness/metallic are explicit scalar values. See [CPU service](../services/images/README.md) for conventions, limitations, deployment and tests. The agent should use linear/non-color imports for data maps and choose the engine's OpenGL/DirectX convention.

Native update required for settings commands and shared runtime. A UI-only activation cannot install the native reader, OS vault integration or shared tool files. Publication does not interrupt active agents; install through the normal idle native-update flow. Windows/Linux live qualification remains separate from Mac/browser and CPU API acceptance.

## Reference images and iterative editing (0.2.113)

Attach a PNG/JPEG/WebP and ask «Перерисуй это в стиле аниме». Enki privately stages original bytes for the actual engine/session/message, while the agent selects `image_inputs` → `edit_image(source=attachment:1)` → status → results. Follow-up «Поменяй волосы на синие» uses `source=latest`, the last completed primary image in this session. «Перерисуй исходник заново» can reuse the retained original; a new attached original replaces it. Source hashes, normalized geometry and actual inference mode/steps are recorded in each manifest. Original input is private, excluded from public result downloads and ZIP.

For new images the agent writes a short visual description; for edits it writes a concise English instruction specifying what must change and what must remain unchanged. It preserves unrequested details and reviews the actual returned pixels when its model supports Vision. A text-only chat model can forward a real reference to the image service, but gets an explicit named reference instead of incompatible image input and must not claim visual review. Ordinary Vision attachments exceeding edit limits still reach the chat model and are marked unsupported for editing.

**At most two total generation jobs per human request**: initial plus one correction, across image/material/icon/edit tools. This is enforced by a durable per-session journal under a native OS file lock, survives process restarts and concurrent calls, and does not refill on automatic timer wakes. Identical request keys are scoped to the real session/message. A lost acknowledgement is recovered with a read-only lookup, never a replayed POST. A new human message grants a new two-attempt budget.

Auto edits use a qualified, instruction-trained **FLUX.2 Klein4B** INT4 profile with actual reference conditioning,4 distilled steps and guidance1. This addresses the demonstrated SDXL failure to obey hair-color changes. Default edit output is approximately512px area at source aspect; on the Xeon12-thread qualification a blue-hair edit took131s and kept the overall composition. Larger explicit outputs take longer and must be multiples of16. The service preloads SDXL for drawing and Klein for editing at startup and keeps **both resident** between jobs; one serialized queue controls CPU work. Combined steady RSS in qualification was approximately30.4GiB; the service cap is64GiB, with at most one additional optional pipeline variant. Health reports actual resident/loading state. Drawing with SDXL and a corrective Klein edit can be combined within the same two-job budget.

Explicit `sdxl-lightning` retains the previous whole-frame redraw/style-transfer path with the exact2-step schedule; strength .5–.95 quantizes to one actual denoise step. This legacy strength is **not** an instruction-editing control and is omitted for Klein. Neither workflow promises exact pixel preservation or masked local retouching. Alpha is composited on white; transparency is not preserved. Source aspect is retained by default, including EXIF rotation; changing canvas uses contain/letterboxing, never silent cropping. Current editing requires the Enki CPU provider. The generic OpenAI-compatible adapter remains text-to-image only and reports unsupported editing explicitly.

Edit input limits: four attached originals, each8MiB, combined16MiB, PNG/JPEG/WebP, <=4096 per side and16MP. Local generated PNGs are hash-checked before reuse, so follow-up editing can continue after the server’s seven-day cleanup. New native installation is required for trusted context/OS-lock CLI and updated shared tools; UI-only hot activation cannot supply them.
