# Переименование в Enki

Приложение называется Enki (Энки), защищённая сессия — «Мастерская».
В Enki 2.0 единственное рабочее ядро — Pi SDK, поставляемое вместе с приложением.
Отдельная установка движка не требуется. История прежних OpenCode и Pi CLI
доступна как архив; продолжение переносится в проверенную сессию Enki.
Внешние установки, их конфигурация и исходная история не изменяются.

## Совместимое обновление

Старые нативные клиенты отклоняют исходники с другим `productName`.
Переходные версии 0.2.82–0.2.83 ещё собираются в совместимом формате, но умеет проверять
и устанавливать Enki. Hub сохраняет этот подписанный переходный релиз для
старого маршрута `/api/updates/stable`. После его установки клиент читает
`/api/updates/enki/stable` и получает следующий релиз Enki. Preview независим.
Переходные пакеты защищены от сборки мусора. Подписи и ключ доверия не меняются.
`/downloads/latest` всегда указывает на последний релиз для ручной установки.

## Данные

При первом запуске нового нативного приложения, до загрузки интерфейса и агентов,
собственные данные переносятся из `opencode-desktop` в `enki` в прежнем родительском
каталоге: `$HOME/.local/share` на macOS, выбранном XDG data root на Linux,
`%LOCALAPPDATA%` на Windows. Используется атомарное переименование в одном
файловом разделе, а не копирование и удаление.

В старом месте остаётся ссылка (junction на Windows). Она нужна для абсолютных
путей, уже записанных движками в сессиях, вложениях и проектах. Это один и тот же
каталог: изменения видны через оба пути. Не удаляйте ссылку, пока старые сессии
ссылаются на неё. Новые удалённые рабочие папки создаются под `enki`; существующие
удалённые папки не перемещаются без проверки работающих процессов на том хосте.

Журнал намерения и системная блокировка позволяют завершить перенос после
аварийного выхода. Если создание ссылки не удалось, перенос откатывается.
Если оба пути содержат разные данные, миграция останавливается без объединения
и перезаписи. Работающий предыдущий экземпляр также блокирует перенос.

Постоянный bundle identifier и ключи существующих хранилищ остаются
идентификаторами совместимости для WebView localStorage/IndexedDB, очередей,
черновиков и системного сейфа. Их нельзя просто заменить строковой
подстановкой: получился бы новый пустой профиль. Разрешения macOS зависят
также от подписи: локальная ad-hoc сборка может запросить их повторно.
Постоянный bundle identifier сам по себе не гарантирует сохранения разрешений.
Старые имена допустимы только в явных адаптерах миграции, истории протокола,
закреплённых ключах и документации о переходе.

Миграция не отправляет промпты, не запускает старые задания, не меняет модели
и не удаляет пользовательские данные. Установка по-прежнему ждёт простоя;
публикация обновления сама по себе не перезапускает приложение.

### Переход на Enki 2.0 (единая среда выполнения) — очереди, таймеры, история

- История OpenCode и чатов Pi CLI импортируется только для чтения (оригиналы,
  WAL и сессии не меняются). Продолжить архив можно только явным проверенным
  продолжением; ничего из истории не отправляется повторно.
- Очереди и таймеры прежнего интерфейса переносятся через журнал среды
  выполнения (`/migrations/cutover`): полная копия каждого элемента (вложения,
  модель и вариант, порядок, «доставка не подтверждена») сохраняется до
  публикации. Очередь приходит на паузе, таймер на паузе создаётся сразу
  выключенным. Копия в настройках удаляется только для элементов с
  подтверждением; общего флага «перенесено» нет. То, что нельзя сопоставить с
  чатом, видно в «Требует внимания» с причиной и кнопками повтора/отказа.
- Для потерянного подтверждения старой отправки «не найдено» в журнале новой
  среды означает «неизвестно», а не «не отправлялось»; повторной отправки нет.
- Настройки и ключи Pi переносятся только явной командой через системное
  хранилище ключей и применяются после перезапуска среды выполнения.

### Каноническое хранилище сессий Enki (2.0.4)

У каждой папки проекта в хранилище среды выполнения есть одна настоящая запись:
канонический путь (`realpath`). Транскрипты раскладываются по шардам
`runtime/sessions/<sha16(канонический путь)>`, и этот путь записывается в строки
`directory` во всех долговечных таблицах (метаданные чата, очередь, таймеры,
квитанции команд, журнал событий).

Прежние версии ключевали шард по строке, как папку назвал клиент. Ссылка старого
каталога данных (`opencode-desktop` → `enki`), переименованный репозиторий или тот
же том в другой точке монтирования давали один и тот же каталог с двумя разными
строками: чат продолжения получал канонический путь в метаданных, а его историю
среды выполнения писала в шард старого написания. Проверка «история принадлежит
рабочему хранилищу» считала такой файл чужим, и в чате не проходит ни один запрос
(в «Мастерской» отказывали и промпт, и смена модели).

Теперь при каждом запуске среды, до восстановления очередей и таймеров и до
открытия любого воркера, включается перенос (`session-shard` в `migration_journal`):

- транскрипт каждого собственного чата переезжает в канонический шард своей
  папки; ссылка создаётся до изменения метаданных, контрольная сумма сверяется,
  прежнее место удаляется только после подтверждения записи в базу;
- строки `directory` этого чата во всех долговечных таблицах заменяются тем же
  каноническим путём в одной транзакции;
- неоконченный журнал предыдущего запуска доводится до конца или откатывается
  (оба направления проверены тестами), пустой старый шард удаляется;
- перенос повторяемый: второй запуск ничего не меняет; незанятые внешние файлы,
  недоступные тома и архивные копии Pi CLI остаются на своих местах, а причину
  видно в `GET /migrations` в поле `shards`.

Ссылка `opencode-desktop` остаётся совместимостью для старых абсолютных путей, но
среда выполнения больше не зависит от неё: чат доступен по обоим написаниям и
везде пишет в один шард. Данные пользователя при переносе не удаляются: меняются
только расположение транскрипта и написание пути в метаданных.

## Имена пакетов и исходников

Начиная с 0.2.84 продукт и нативный пакет называются Enki/enki, основной
исполняемый файл — `enki`; `opencode-desktop` остаётся совместимым CLI-входом
для прежних MCP-регистраций. На macOS старый путь `.app` становится ссылкой
на `Enki.app`, не отдельной второй установкой. Отдельно установленное приложение
по этому старому пути автоматически не перезаписывается.
На Windows переносится также собственный профиль браузера из
`%USERPROFILE%/.opencode-desktop` в `.enki`, с junction для старых путей.
Private release operator переносит `~/.config/arvela-release` в `enki-release`,
сохраняя старые абсолютные пути файлов ключей через ссылку; `ENKI_*` переменные
предпочтительны, прежние `ARVELA_*` принимаются как совместимые псевдонимы.
Исторические исходные снимки тестов сохраняются побайтово: их контрольные суммы
являются частью доказательств прежних замеров, а не именем текущего приложения.

Второй переходный релиз 0.2.83 обновляет также алгоритм нативного отпечатка:
старый алгоритм исключал номер версии только у Rust-пакета с прежним именем.
Поэтому Hub сохраняет именно последний совместимый переходный релиз; клиентам
без перехода не предлагаются непроверяемые ими исходники нового пакета.

Стандартные инструкции мастерской и встроенного навыка управления компьютером
обновляются при запуске только при совпадении SHA256 с прежним опубликованным
шаблоном. Пользовательские правки и сторонние навыки не перезаписываются.

Движки сохраняют историческую строку каталога сессии. Для «Мастерской» нативный
слой проверяет, что старый и новый пути ведут в одну папку; интерфейс открывает
существующий ID по прежнему пути. Потеря настроек также не создаёт второй чат:
поиск проверяет оба подтверждённых каталога. Посторонний каталог не принимается.

В Linux пакет `enki` объявляет замену и конфликт только с прежним пакетом
приложения `arvela`; RPM объявляет `Obsoletes` для него. Независимый пакет
движка OpenCode не помечается к удалению. Это штатная схема
[Debian Conflicts/Replaces](https://www.debian.org/doc/debian-policy/ch-relationships.html)
и [Tauri Linux package metadata](https://v2.tauri.app/reference/config/#debconfig).
Древние ручные установки под другими именами требуют отдельной проверки
принадлежности пакета; они не удаляются по совпадению названия OpenCode.

`scripts/test-package-migration.py` проверяет замену реальным `dpkg` в отдельном
корне и базе пакетов, включая сохранение пользовательского файла и совместимого
CLI. Это проверка пакетной миграции, а не проверка Linux GUI. Она включена в Linux CI.
