# Самодоработка с любого подключённого устройства (0.2.104)

«Мастерская» использует `npm run release:local -- stable` на macOS, Windows и Linux.
Команда выполняет полный набор frontend/Hub/ASR/Rust проверок и собирает UI.
Если локального operator.json нет, выбирается публикация с ключом устройства.
Для явного выбора задайте `ENKI_RELEASE_MODE=device`. Приватный ключ подписи
и административный ключ Hub на клиентском устройстве не нужны.

Установите **нативный Enki0.2.104+**, подключите его к своей библиотеке Hub.
В RUNTIME.json мастерской есть `nativeExecutable`; задайте этот абсолютный путь
в `ENKI_NATIVE_EXECUTABLE`. Нативная CLI читает ключ из vault, не выдавая его агенту.
Источник из ZIP без .git нужно сначала превратить в локальный Git-репозиторий
и закоммитить. GitHub-аутентификация нужна только для push, а не для выпуска Hub.

Hub принимает оба полных пакета по `POST /api/updates/device`, проверяет версии,
пути, размеры, идентичность приложения и вычисляет нативный отпечаток из исходников.
Отдельная локальная служба `enki-release-signer` подписывает пакеты прежним
закреплённым ключом. Она доступна только Unix-socket процессу Hub, не выполняет
загруженный код и не предоставляет ключ процессу HTTP. Подписанный ключ версии
не меняется. Проверки качества выполняются на устройстве: Hub хранит его
утверждение об успешных проверках, но не выдаёт его за серверный запуск тестов.

Все действующие ключи устройств принадлежат одному владельцу и теперь позволяют
выпускать код для его клиентов. Отзыв устройства лишает его этого доступа.
Остальные административные API остаются закрыты. Подпись централизована онлайн;
считайте сервер подписи доверенной частью инфраструктуры выпуска и включайте
его приватные файлы в защищённые резервные копии. Старый локальный operator
остаётся совместимым альтернативным путём.

Перед работой с другого устройства получите актуальные исходники стабильного
релиза Hub или main, уже включающий этот релиз. Не повышайте только номер версии
в устаревшей копии: CAS защищает гонку публикации, но не объединяет изменения
разных рабочих копий.

При конфликте версии/канала требуется обновить базу и повторить проверки.
Потерянный ответ POST не вызывает повторную отправку: publisher сверяет head
и оба пакета. Успех записывается в .local/releases/<version>-stable.json только
после проверки скачанных байтов и обеих подписей закреплённым публичным ключом.
Релиз предлагает обновление всем клиентам; установка и перезапуск отдельно.

Для headless-агента задайте абсолютный `ENKI_HUB_DEVICE_CONFIG` — приватный JSON
с `endpoint`, `certificateFile` (публичный PEM) и `keyFile` (его отдельный
device-ключ). JSON и ключ должны быть обычными файлами с Unix-правами0600.
Секреты нельзя передавать в командной строке или добавлять в исходники.

## Прежняя настройка локального оператора

# Мастерская

Над списком проектов находится один закреплённый чат **Мастерская**.
Он создаётся при первом локальном подключении к встроенному Enki Runtime, без
отправки задания модели и без изменения выбранного пользователем чата. При
первом открытии используется тот же реальный session ID. Ошибка ядра не создаёт
новый чат; после потерянного ответа создания сначала проверяется существующая
сессия. Сохранённая мастерская 0.2.x из архива OpenCode продолжается проверенным
идемпотентным продолжением ядра в том же каталоге: история сохраняется, ничего
не переотправляется, пустая замена не создаётся.

Каталог `<данные Enki>/workshop` — отдельный защищённый проект, не рабочая
копия исходников. Он скрыт в обычном списке проектов, а чат не дублируется в
недавних. Удаление, архивирование, переименование чата и скрытие его проекта
блокируются в store, не только отсутствием кнопок. Внешнее удаление через
файловую систему/администратора ОС этим не запрещается. При подтверждённом
404 штатное открытие восстанавливает точку входа; утраченный transcript не
объявляется восстановленным. История остаётся в Enki Runtime, пользовательские
чаты не переносятся и не удаляются.

Мастерская локальная: при SSH-подключении сначала выберите «Этот компьютер».
Текущий сервер/рабочее пространство разделяют её идентификатор через endpoint
preferences; локальный путь не отправляется удалённому серверу. Защищённый чат
выполняет встроенный Enki Runtime; ядро помечает сессию как мастерскую и
добавляет политику выпуска в её системный prompt.

## Контекст агента

При подготовке native создаёт приватные файлы:

- `AGENTS.md` — начальные системные инструкции проекта, автоматически читаемые
  Enki Runtime. Их исходник: `src-tauri/resources/workshop/AGENTS.md`.
  Локальные пользовательские изменения сохраняются при следующих открытиях;
  неизменённая копия прежнего шаблона обновляется (`migration::bundled_defaults`).
- `WORKSPACE.json` — путь проекта и проверенная папка исходников (или null).
- `RUNTIME.json` — платформа, версия native и команда выпуска, без секретов.

Исходники определяются по package name и стабильному Tauri identifier: сначала
сохранённый путь, затем `workshop/source`, затем папка компиляции, если она ещё
существует. Иначе агент должен подготовить новую рабочую копию; готовность
исходников не подделывается. Явно привязать другую существующую копию можно:

```sh
"/Applications/Enki.app/Contents/MacOS/enki" --workshop-prepare /absolute/path/to/arvela
```

На Windows/Linux используйте установленный executable с теми же аргументами.
Команда меняет только собственные файлы мастерской, не вызывает модель, не
публикует релиз, не читает ключи. Каталог/файлы symlink отвергаются. Править
локальный AGENTS.md допустимо по заданию владельца; для последующих установок
нужно согласованно править и bundled-шаблон в исходниках.

Инструкции требуют анализ кода/репродукцию, регрессионные тесты и их запуск,
независимый просмотр diff, сохранение чужих изменений и границ сессий. Тесты
меняются при изменении реального контракта; удалять или ослаблять проверки ради
зелёного результата нельзя. Публикация изменений по заданию владельца ожидается
после проверок; явный запрет выкатывать и просьба только про анализ приоритетнее.
Применение обновления к работающей мастерской отдельно не выполняется.

## Локальный оператор релизов

`npm run release:local -- stable` работает из корня репозитория. До доступа
к credentials она требует чистое закоммиченное дерево, npm test/build,
архитектуру/bundle budgets, release tests, Python3 Hub tests, Cargo fmt/tests
и строгий Clippy. Только затем вызывается существующий `scripts/releases/publish.mjs`
с приватным окружением. Канонический publisher подписывает полные UI/source,
публикует CAS stable/preview и проверяет served head/оба скачивания. Успехом
считается `.local/releases/<version>-<channel>.json`, не вывод об upload.

Настройка текущего компьютера: `~/.config/arvela-release/operator.json`
(либо путь из `ARVELA_RELEASE_OPERATOR`), на Unix файл и secret-файлы 0600:

```json
{
  "hubUrl": "https://your-hub:8443",
  "caFile": "/absolute/path/to/public-hub-ca.crt",
  "adminTokenFile": "/private/path/to/admin-token",
  "signingKeyFile": "/private/path/to/updater.key"
}
```

В adminTokenFile только токен без JSON. Необязательный signingPasswordFile
задаёт пароль существующего ключа. Пути абсолютные; небольшой обычный приватный
файл обязателен, symlink не разрешён. На Windows используйте закрытый каталог
пользователя и соответствующий ACL. Самих значений ключей нет в проекте,
настройках UI, системном prompt или RUNTIME.json. Read-only проверка настроек:

```sh
npm run release:local -- --check
```

Обычный Windows device-key не имеет права публикации. Приватный ключ подписи
не нужно распространять на каждый клиент: выпуск выполняется на доверенном
компьютере оператора; другая машина готовит изменения/PR. Если operator/toolchain
не настроены, агент должен сообщить конкретный блокер. Нельзя обходить TLS,
подписи, менять native fingerprint или объявлять неуспешные проверки пройденными.

После публикации текущие клиенты сами видят зелёный UI либо жёлтый source-update.
Последние исходники также доступны через `/downloads/latest/source.zip` для
старых клиентов. Ключи и приватная история никогда не входят в публичный ZIP.

## Постоянный договор выпуска (0.2.64)

Владелец разрешил мастерской коммит и штатную публикацию по умолчанию для задач
на изменение кода Enki. Дополнительное «сделай релиз» не требуется. Интерфейс
добавляет это поручение к каждой ручной отправке, очереди/уточнению и расписанию
только защищённого чата; другие чаты не получают новых разрешений. Общий текст —
`src/workshop/policy.ts`. Из истории отделяется только точное известное
напоминание той же сессии при live/reload, сохраняя текст пользователя,
вложения и ответ агента.

Агент обязан проверить, что именно его файлы попали в фактически опубликованный
пакет; наличие другого обновления или успешная сборка не означают доставку.
Чужой незавершённый diff сохраняется; свой проверенный коммит можно выпустить
из чистой изолированной копии с отдельными зависимостями. Если выпуск заблокирован,
итог должен прямо сообщать «код изменён, обновление НЕ выпущено» и причину.
Просьба только об анализе или прямое «не выкатывать» приоритетнее. Публикация
по умолчанию предлагает обновиться; она не разрешает установку или остановку
агентов. Повторение инструкций не является автоматическим выполнением релиза:
тесты/подпись/каноническая квитанция остаются обязательной проверкой оператора.
