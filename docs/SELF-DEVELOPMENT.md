# Мастерская и выпуск с подключённого устройства

«Мастерская» — защищённый проект и чат для изменения Enki. В начале задачи агент
читает `WORKSPACE.json` и `RUNTIME.json`: там папка исходников, платформа,
установленная версия и доступный нативный executable. Ресурс
`src-tauri/resources/workshop/AGENTS.md` задаёт цикл работы; изменённый пользователем
шаблон не перезаписывается без проверки происхождения.

## Работа с кодом

Агент читает текущие `AGENTS.md`, `.pi/TASK.md` и относящиеся к задаче документы,
воспроизводит проблему, исправляет её, обновляет содержательные тесты и выполняет
[обязательные проверки](VERIFICATION.md). Секреты и история не копируются в
исходники или prompt. Чтение checkpoint не запускает прежние задания.

По поручению владельца мастерская публикует проверенное изменение. Просьба только
про анализ или явный запрет выпуска имеют приоритет. Применение обновления к
работающему приложению — отдельное действие с сохранением данных и простоем.

## Выпуск через Hub

```sh
npm run release:local -- stable
```

Команда требует чистый проверенный commit, запускает все gates и вызывает штатный
publisher. Подключённое устройство может публиковать своим ключом через изолированный
signer Hub; приватный ключ подписи и admin key на него не копируются. Настройте
`ENKI_RELEASE_MODE=device` и `ENKI_NATIVE_EXECUTABLE` из `RUNTIME.json`, если требуется
явный выбор. При отсутствии operator config режим устройства выбирается автоматически.
Headless-вариант использует приватный `ENKI_HUB_DEVICE_CONFIG` своего устройства.

Hub повторно проверяет файлы, версии, identity и native fingerprint, полномочия
устройства и версию канала. Отозванный ключ или конфликт канала не обходятся.
Загруженный исходный код никогда не выполняется на Hub. Signer доступен только
через защищённый локальный socket; клиент не получает его ключ.

Успех подтверждают `.local/releases/<version>-<channel>.json`, served head и
оба проверенных подписанных пакета. После этого публикуют тот же commit в Git.
Доступ к GitHub и доступ к Hub — отдельные полномочия.
[Форматы и порядок обновления](HUB-UPDATES.md).

## Локальный оператор

Дополнительный административный путь использует
`~/.config/enki-release/operator.json` либо `ENKI_RELEASE_OPERATOR`.
Файл ссылается на HTTPS Hub, публичный сертификат и отдельные приватные файлы
admin token/ключа подписи. На Unix config и secret files должны быть обычными
файлами 0600; на Windows — закрытый пользовательский каталог и ACL.

```json
{
  "hubUrl": "https://your-hub:8443",
  "caFile": "/absolute/path/to/public-hub-ca.crt",
  "adminTokenFile": "/private/path/to/admin-token",
  "signingKeyFile": "/private/path/to/updater.key"
}
```

`npm run release:local -- --check` проверяет настройки без публикации. Значения
ключей не выводятся и не добавляются в Git. Настроенный оператор не является
обязательным условием для устройства с правом выпуска через Hub.

## Если выпуск не состоялся

Сохраните проверенные изменения и конкретную диагностику. Сообщите отдельно:
что изменено, что проверено, опубликовано ли обновление и установлено ли оно.
Не меняйте fingerprint, не выключайте подпись/TLS и не создавайте квитанцию вручную.

Готовые установщики публикуются после проверенной публикации Hub: тот же commit
должен находиться в GitHub main, затем оператор запускает
`npm run release:packages -- stable`. Обычный push не выкладывает установщики.
Дождитесь успеха всех трёх платформ и проверьте подписанный ответ Hub native
updates. Исходники, готовые пакеты и установленное приложение отмечайте отдельно.
