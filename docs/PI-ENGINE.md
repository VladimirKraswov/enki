# Pi SDK внутри Enki 2.0

Исполняющее ядро одно: **Enki Runtime** в
`src-tauri/resources/agent/`. Оно встраивает Pi SDK через API `AgentSession` и
`ModelRuntime`; отдельно установленный Pi CLI не нужен. Текущие закрепления —
SDK **0.85.1** и Node **24.22.1**; источник истины —
`scripts/runtime/sdk-contract.mjs`, `runtime-lock.json` и проверенные lockfiles.
Их обновляют совместно по [SDK-UPGRADE.md](SDK-UPGRADE.md).

## Как приложение связано с ядром

```text
UI → AgentBackend → src/agent/runtime → Enki Runtime → Pi SDK
                         ├ этот компьютер: нативный супервизор, loopback + bearer
                         └ SSH-хост: проверенный runtime ensure + SSH-туннель
```

Нативная часть запускает проверенный ресурс приложения с его встроенным Node;
она не ищет `pi`/`opencode` в PATH. Одновременные подключения переиспользуют
один супервизор runtime; отдельные чаты используют сессии SDK внутри него.
Удалённый хост не заменяется локальным при ошибке связи. Транспорт и события
описаны в [AGENT-BACKENDS.md](AGENT-BACKENDS.md), владение процессами — в
[ARCHITECTURE.md](ARCHITECTURE.md), установка удалённого ядра — в
[REMOTE-RUNTIME.md](REMOTE-RUNTIME.md).

## Сессии и рабочие возможности

Runtime владеет журналом команд/событий, метаданными, очередями и таймерами в
`runtime.sqlite`, транскриптами SDK в `sessions/`, подготовленными вложениями и
архивами `legacy/`. Раскладка задаётся `platform/paths.ts`; локальный каталог
ядра — `<app-data>/runtime`. UI не ведёт параллельную базу разговоров.
Подтверждение приёма промпта ещё не означает завершение; переподключение сверяет
авторитетное состояние, не воспроизводя потенциально исполненную команду.

Контекст, сжатие, выбор модели, fork/продолжение, терминал, изменения Git,
очередь, таймеры, диалоги расширений, браузер и MCP идут через текущий контракт
ядра. Доступность конкретной поверхности задаётся `AgentBackend.capabilities`;
таблица возможностей старого Pi CLI к ней не применяется. См.
[настройки](SETTINGS.md), [контекст](CHAT-CONTEXT.md) и
[очередь/диктовку](CONTEXT-QUEUE-VOICE.md).

Настройки «Агент Enki» принадлежат подключённому runtime. Локальные ключи
провайдеров обслуживаются нативным брокером/системным хранилищем; явный режим
удалённого agentDir использует файлы этого собственного каталога Enki.
Не редактируйте глобальные `~/.pi` и конфигурацию стороннего OpenCode.
Hub-каталог применяет Pi-описания к Enki; готовность управляемой модели и
аренду GPU контролирует runtime ([MODEL-SERVICES.md](MODEL-SERVICES.md)).

## Расширения, MCP и доступ

Общие MCP и навыки подключаются из явного реестра Enki. Пути расширений,
шаблонов, навыков и локальных пакетов задаются в настройках ядра; их диагностическое
состояние видно там же. Пакет — доверенный локальный код, а не разрешение
автоматически устанавливать npm/git-зависимости. Поддерживаемая граница UI API,
порядок ресурсов и ограничения пакетов документированы в
[SDK-UPGRADE.md](SDK-UPGRADE.md); совместимость с любым будущим плагином не обещается.
Встроенный LSP живёт в `agent/src/extensions/lsp.ts` и владеет только своими
stdio-серверами, без внешнего постоянного демона.

Режимы чтения, запроса и полного доступа проверяются общей политикой runtime.
Запомненные разрешения и ожидающие вопросы принадлежат чату; неизвестный
инструмент не становится read-only по имени. Отсутствие ответа не является
согласием. «Полный доступ» не требует повторного разрешения для уже разрешённого
действия; явные запреты и системные разрешения ОС остаются самостоятельными.

## Обновление и история 0.2.x

SDK поставляется как часть проверенного релиза Enki, не обновляется командой
глобального Pi CLI. Установка ждёт простоя, сохраняет парную копию БД и изменяемых
JSONL и восстанавливает согласованное состояние при откате; детали в
[SDK-UPGRADE.md](SDK-UPGRADE.md). Стабильный OS identifier и существующие
пространства ключей нельзя менять ради нового названия.

В 0.2.x существовал второй бэкенд `pi --mode rpc` рядом с OpenCode. Его выбор
движка, внешние пути, JSONL RPC, таблица ограничений и старые Linux/macOS smoke
результаты — история прежней реализации, не инструкция и не приёмка SDK 2.0.
Датированные доказательства сохранены в [VERIFICATION.md](VERIFICATION.md) и
истории исходников. Оригиналы OpenCode/Pi CLI не запускаются и не изменяются:
они доступны через проверенный импорт только для чтения, а продолжение
создаётся явно с происхождением в новом Enki-чате
([ENKI-MIGRATION.md](ENKI-MIGRATION.md)).

Статус этой редакции — документация текущего исходного контракта. Финальная
сборка, платформенные CI и живая приёмка Enki 2.0 должны иметь отдельные
квитанции; старые PASS не заменяют их.
