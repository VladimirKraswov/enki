# Общие навыки и инструменты — Enki 2.0

Настройки → **Навыки и инструменты** — один каталог навыков и MCP-сервисов для
встроенного ядра **Enki Runtime** (закреплённый Pi SDK). Есть область «Весь
компьютер» и дополнительные источники/сервисы «Этот проект». Общие записи в
проекте показаны только для чтения: изменять их нужно в общей области.
Идентификаторы не должны пересекаться между областями.

До 2.0 этот каталог синхронизировался в два агента (OpenCode через его
`opencode.jsonc` и Pi CLI через `--skill`/адаптер). В 2.0 внешних агентов нет:
каталог читает только ядро Enki, а настройки внешних установок OpenCode/Pi не
изменяются и не читаются.

## Навыки

Навык — каталог `<name>/SKILL.md`, при необходимости со скриптами и примерами.
Источник навыков подключается **явно**, абсолютным путём через UI (например,
ваш `~/.agents/skills`). Файлы навыков не копируются и не редактируются, поэтому
исправление навыка остаётся в одном исходном файле. При изменении пути
подключённого источника выключите старую запись и добавьте новую с другим
идентификатором.

Ядро загружает **только включённые источники реестра** (`loadSkills` SDK с
`includeDefaults: false`). Стандартные каталоги `~/.agents/skills`,
`~/.pi/agent/skills` и `.agents/skills` проекта сами по себе не
обнаруживаются: чтобы навык работал в Enki, подключите его каталог источником.
Отдельные навыки, шаблоны, расширения и локальные пакеты Pi можно также указать
путём в `Настройки → Агент Enki → Расширения и LSP` ([настройки](SETTINGS.md)).
При совпадении имён побеждает первый: общие навыки Enki (реестр, браузер,
компьютер), затем локальные пакеты, затем отдельные пути — как в Pi SDK
([обновление ядра](SDK-UPGRADE.md)).

Формат: обязательные YAML `name` (1–64 символа, строчные буквы/цифры с
одиночными дефисами, совпадает с каталогом) и `description` (1–1024 символа).
Указывайте реальные программы и зависимости в тексте навыка.

Каталог в UI читает только метаданные: не более 3000 записей, глубина 8, файл
64 КиБ, ссылки не обходятся, об ограничении сообщается. Наличие файла не
означает, что разрешения позволяют его использовать или что его зависимости
установлены. Состояние навыка в UI честное: ядро не сообщает, какие навыки оно
загрузило, поэтому «найден агентом» не утверждается. Текст навыка загружается
моделью по необходимости (или явно командой `/skill:имя`).

Отключение источника убирает его из следующих сессий. Из уже использованного
контекста текст навыка не исчезает.

## Общие исполняемые инструменты (MCP)

Переносимый инструмент живёт в **MCP-сервисе**. Enki хранит одну спецификацию
подключения; ядро подключает сервисы общим пулом и регистрирует их инструменты
как `mesh_<service-id>_<tool-name>` штатным API расширений SDK. Второго
агентского цикла нет.

Поддерживаются:

- **stdio**: абсолютный путь к программе и JSON-массив аргументов. Shell не
  используется; для npm-команд укажите Node и JS-файл. `.cmd`/`.bat` напрямую
  не запускаются. Сервис получает cwd реального проекта и ровно идентичность
  профиля Enki. Указанные имена переменных берутся из окружения запущенного
  Enki, значения в реестр не записываются. Finder/Windows launcher могут не
  наследовать окружение терминала.
- **Streamable HTTP**: HTTPS или loopback HTTP, без секретов/query/fragment в URL.
  Необязательный Bearer хранится в системном хранилище ключей и передаётся
  нативным мостом только нужному HTTP-клиенту. UI не читает сохранённый токен
  обратно. При изменении URL проверьте назначение токена; авторизацию можно
  убрать в форме.

Не поддерживаются OAuth/SSE, MCP resources/prompts и серверная sampling. Ошибка
инструмента MCP (`isError`) передаётся модели текстом (с ограничением размера);
в истории чата сохраняется ограниченная сводка результата, а изображения —
только в самом ответе инструмента. Браузер — отдельный общий сервис со своими
режимами, профилем и защитой координат; каталог содержит переход к его
настройкам.

MCP roots передают рабочий каталог серверу, **это не OS sandbox**. Используйте
сервисы, которым доверяете; права их процесса определяет операционная система.
Подтверждения инструментов выдаёт политика доступа чата Enki; каталог не
добавляет `allow` и не отменяет разрешения.

## Установка, состояния и применение

Для MCP один раз нажмите **Установить мост**. Требуется Node (поиск/явный путь,
как у браузера) и npm. Проверенный абсолютный путь Node сохраняется для запуска
из Finder/Windows launcher; после изменения явного пути нажмите «Проверить мост».
Закреплён MCP SDK 1.32.0, `npm ci` по lockfile, без install scripts и второго
Chromium. Установка ограничена 180 с, собственные процессы останавливаются при
выходе. Для навыков MCP SDK не нужен.

Запись реестра проверяет ожидаемое содержимое, делает резервную копию и
сохраняет атомарно. После **подтверждённой** записи UI просит ядро этого
компьютера обновиться: новые чаты получают изменения сразу, свободные открытые
чаты переоткрываются, занятые — после завершения текущей работы. Ничего не
прерывается и не повторяется; уведомление сообщает, сколько чатов обновлено и
сколько ждут. Во время работающих агентов изменение подключений заблокировано.
Неуспешное действие автоматически не повторяется.

**Проверить MCP** подключается и читает список инструментов, не вызывает их.
**Обновить статус** перечитывает каталог; состояние MCP приходит отчётами
открытых чатов ядра. Ответ probe, наличие SDK и наличие SKILL.md не подменяют
фактическую работу в чате.

Каталог настраивается на этом компьютере. Ядро на SSH-хосте не получает навыки и
MCP этого компьютера; у удалённого хоста свой профиль и свои ресурсы.

## Хранение и проверки

Нативный каталог: `capabilities/global.json`, `capabilities/project-<hash>.json`
и `capabilities/runtime` внутри app data. Stable identity не меняется:
macOS `~/.local/share/enki`, Linux — разрешённый XDG data root,
Windows `%USERPROFILE%/.enki` (прежний `.opencode-desktop` читается при
миграции; вне перенаправления AppData в MSIX). Отдельный профиль
`ENKI_PROFILE_DIR` использует только `<profile>/capabilities`: домашний каталог
владельца не читается, ссылка в пути профиля отклоняется. Реестры/секреты в Git
не попадают.

Автоматические тесты проверяют конфликты записи, отказ устаревшим
инструментам, ограниченные детали результатов MCP, обновление открытых чатов
после записи и границу профиля (в том числе вспомогательный скрипт
`create-shared-skill/scripts/catalog.py`). Opt-in
`node src-tauri/resources/shared/test/acceptance.mjs <absolute-runtime>`
использует настоящий SDK: метаданные без вызовов, JSON Schema-валидацию,
выполнение только собственного fixture, cwd, отсутствие повторения и отказ после
отключения. Он не отправляет модельных запросов. Live Windows/Linux-проверки
остаются обязательными: проверка на Mac не доказывает их прохождение.

Официальные материалы: [Pi skills](https://github.com/badlogic/pi-mono/blob/main/packages/coding-agent/docs/skills.md),
[MCP roots](https://modelcontextprotocol.io/specification/2025-11-25/client/roots).
