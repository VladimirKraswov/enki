# Слой агент-бэкенда

## Что реализовано (2.0)

Исполняющий агент **один** — встроенный Enki Runtime: закреплённый Pi SDK на
закреплённом встроенном Node (`src-tauri/resources/agent`, правила обновления —
[SDK-UPGRADE.md](SDK-UPGRADE.md)). Все рабочие чаты используют этот backend. Внешние установки OpenCode/Pi CLI, их службы
и данные Enki не запускает, не останавливает и не изменяет.

Старые истории OpenCode/Pi CLI доступны только для чтения из импортированного
архива и продолжаются в Enki лишь явным продолжением; их ID не отправляются в
другой движок. Старые настройки движка по папке/чату (`projectEngine`,
`sessionEngine`, `newChatEngine`) для исполнения игнорируются
(`src/state/engines.ts`).

## Границы

```text
src/components/          презентация
src/state/store.ts       фасад команд и подписок, выбор проекта/сессии
        ↓ вызывает только AgentBackend
src/agent/backend.ts     контракт (типы, возможности, подписки)
src/agent/registry.ts    connectRuntime(target): этот компьютер или SSH-хост
src/agent/runtime/       клиент, подключение, события, ID, pluginUi/
        ├ этот компьютер → runtime_connection → нативный супервизор → loopback
        └ SSH-хост → connect_remote_runtime → `enki-runtime ensure` → SSH-туннель
```

- Цель выполнения — `{ kind: "local" }` или `{ kind: "remote", host }`.
  Удалённая цель никогда не переключается на локальную: ошибка хоста
  показывается как ошибка хоста.
- Ключ доступа живёт только в памяти; при ротации или перезапуске ядра тот же
  коннектор переразрешает ту же цель (локальную или тот же хост).
- Транспорт принадлежит бэкенду: URL, SSE и заголовки наверх не уходят.
- `AgentBackend.capabilities` описывает необязательные поверхности; UI
  деградирует по возможности, а не по ОС или версии.

## Правила

- каждый вызов, зависящий от каталога, несёт этот каталог явно;
- `prompt` подтверждает **приём** задачи, а не её завершение; прогресс приходит
  событиями;
- запросы разрешений и вопросы показываются пользователю и никогда не
  подтверждаются автоматически;
- переподключение сначала пересинхронизирует авторитетную историю/статусы и
  ожидающие запросы, затем продолжает инкрементальные обновления.
