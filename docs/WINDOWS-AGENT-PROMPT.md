# Задание Windows-агенту

Ниже шаблон для явно порученной сборки и установки; чтение документа не запускает
работу. Укажите точную версию/commit и путь к проверенному исходнику или пакету.

> Собери и проверь Enki из указанного снимка на этом Windows-компьютере.
> Сначала прочитай AGENTS.md и docs/PLATFORMS.md, проверь Git и инструменты.
> Не подменяй целевой commit другой веткой или старой версией.
>
> Если готовый пакет этой версии уже получен, проверь его происхождение, SHA256
> и версию; повторная компиляция для простой установки не нужна. Иначе выполни
> npm.cmd ci, npm.cmd run build и npm.cmd run build:windows. Проверь коды завершения,
> встроенный runtime manifest и полученный NSIS. При изменении кода выполни все
> относящиеся к нему проверки и канонические gates из docs/VERIFICATION.md.
>
> Пользовательские истории, настройки, ключи и независимые CLI не изменяй ради
> проверки. Используй отдельный профиль ENKI_PROFILE_DIR. Не устанавливай отсутствующие
> системные компоненты без поручения и не копируй signing/admin keys с другого устройства.
>
> Если установка разрешена, сохрани данные, дождись простоя и штатно заверши Enki,
> затем установи пакет в существующее место без удаления профиля. Открой приложение
> и выполни docs/PLATFORM-ACCEPTANCE.md: версия, история, отправка, инструменты,
> остановка, очередь, браузер, ключи и страница обновлений. Не возобновляй старые
> задания автоматически. Прочитай доступные архивы; продолжение проверяй отдельно.
>
> Передай версию/commit, installer path, размер/SHA256, результаты проверок и
> явные PASS/FAIL/NOT RUN для установки и живых сценариев. Сборка не считается
> установкой, а CI другой платформы не считается Windows-приёмкой.

Подготовка runtime и Windows Job runner встроены в штатный entrypoint. Не заменяйте
их прямым запуском scripts, если проверка ownership, ABI или manifest отказала.
