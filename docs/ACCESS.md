# Доступ к файлам и системным ресурсам

Есть две независимые проверки: режим инструментов в чате и разрешения ОС.
«Полный доступ» разрешает инструменты по политике Enki, но не выдаёт системный
доступ к микрофону, защищённым папкам, локальной сети или хранилищу ключей.

## Диагностика

1. Определите, что отказало: инструмент, чтение проекта, SSH, Hub или системный сейф.
2. Сохраните черновик. Проверьте выбранный компьютер и фактическую папку проекта.
3. При `EPERM`/`EACCES` проверьте доступ в контексте установленной Enki. Не выводите
   причину «нет разрешения» только из общего HTTP 500 или таймаута.
4. При системном запросе пользователь подтверждает доступ средствами ОС. Не
   меняйте права всей домашней папки, ACL, TCC-базу или сертификаты как обход.
5. После восстановления сначала повторите чтение/проверку соединения. Потенциально
   выполненный промпт сверяйте по квитанции; не отправляйте его заново автоматически.

Установка ждёт простоя и сохраняет данные. Сбой фонового необязательного MCP
должен объяснять недоступность его инструментов, сохраняя обычную отправку.
Настоящие блокирующие ошибки показывают причину и конкретное действие восстановления.

## Подпись macOS

Стабильный bundle identifier не гарантирует сохранение разрешений при каждой
ad-hoc сборке: её идентичность зависит от содержимого. Для распространяемых
Developer ID сборок нужны одна доверенная подпись и штатная нотариализация.
Не создавайте самоподписанный сертификат или ослабленную requirement как замену.

Проверки собранного пакета:

```sh
python3 scripts/verify-macos.py /absolute/path/Enki.app
codesign --verify --deep --strict /absolute/path/Enki.app
codesign -d -r- /absolute/path/Enki.app
```

После смены подписи доступ к Keychain или папкам может потребовать решения
пользователя. Проверка должна происходить из нового приложения; успешное чтение
из Терминала не доказывает доступ Enki. Дочерние процессы запускает и завершает
только супервизор приложения, с сохранением принадлежности и проверяемого состояния.
