# Обновления Enki

Версия в исходниках, опубликованный релиз и установленное приложение — разные
состояния. Обновление должно показывать конкретный этап, причину отказа и способ
повтора; потерянное подтверждение нельзя считать разрешением повторить мутацию.

## Действующий транспорт

Hub отдаёт stable/preview через проверенный HTTPS origin и ключ устройства.
Передача истории может быть выключена: обновления от неё не зависят.
Каждый релиз содержит два полных подписанных пакета — интерфейс `hot` и исходники
`source`. Закреплённый ключ проверяет подпись, версия и native fingerprint
определяют совместимость. В пакеты не входят ключи, локальные receipt или истории.

- Совместимый native fingerprint позволяет заменить UI после сохранения черновиков,
  вложений и журнала диктовки. Нативное ядро при этом не перезапускается.
- Изменение native fingerprint требует нативного пакета. В действующем клиенте
  основной путь — готовый платформенный пакет с GitHub. Hub связывает его
  с опубликованными исходниками и заверяет описание своим ключом; клиент
  проверяет подпись, размер и SHA256 до распаковки.
- Повтор не переиспользует повреждённую попытку: создаётся новый каталог, прежний
  лог сохраняется. Компоненты повторно скачиваются лишь при ограниченном временном
  сетевом сбое; checksum/TLS-ошибка не маскируется повтором.
- Ошибка подписи, несовместимый новый пакет и отмена показываются явно.
  Проверенный старый hot UI после успешной нативной установки снимается как
  заменённый; подлинная порча остаётся ошибкой.

## Готовые пакеты и локальная сборка

Выпуск включает DMG для macOS ARM64, NSIS для Windows x64 и DEB для Linux x64.
Hub проверяет точный commit опубликованных исходников, native fingerprint,
успешный workflow `desktop.yml` на main и GitHub digest каждого из трёх файлов.
Изолированный signer сначала проверяет подпись исходников, затем заверяет
маленькое описание пакетов. Приватный ключ остаётся на Hub.

Кнопка **Скачать** получает готовое приложение. После проверки появляется
**Установить и перезапустить**; во время работы агентов установка ожидает простоя.
Сетевой сбой не запускает компиляцию. Загрузка ограничена по размеру и времени,
разрешены только HTTPS-переходы между GitHub и его CDN. Повтор — явный.
Для больших пакетов время загрузки рассчитывается по подписанному размеру
(от 15 до 60 минут), чтобы медленное соединение не обрывало исправную передачу.
Локальная подготовка среды ограничена 40 минутами, холодная компиляция —
90 минутами при прежнем пределе в два потока. Отмена останавливает только
процессы этой сборки. Ошибки времени ожидания и переполнения журнала различаются.

Если CI ещё работает, интерфейс показывает ожидание пакета. Проверки повторяются
при возвращении в окно, восстановлении сети и каждые пять минут; Hub кеширует
результаты с увеличением интервала до пяти минут, чтобы не перегружать GitHub.
Успешный результат остаётся связан с неизменяемой ревизией опубликованного выпуска.

Индикатор показывает и выпуск подписанных исходников, даже если установщик
ещё не готов. Он открывает настройки и не начинает сборку автоматически.
При отсутствии пакета раздел **Собрать из исходников** раскрыт сразу;
при готовом пакете основным остаётся скачивание установщика.

**Собрать на этом компьютере** доступно после проверки Node.js/npm,
Rust/Cargo и системных инструментов Tauri. Это работает и на Windows:
GitHub Actions и вход в GitHub для этого пути не нужны. Исходники поступают
из Hub с проверкой подписи, сборка идёт в отдельной папке, установка ждёт
авторитетного простоя Runtime. Это не полностью автономная сборка: инструменты
и зависимости по lockfile загружаются из своих источников. Недоступность всего
GitHub может затронуть отдельные зависимости; отсутствие прав на Actions — нет.

Установленные клиенты до 2.0.6 используют свой прежний механизм до обновления
нативного приложения. Итоговая приёмка 2.0.6 пока в [ROADMAP](../ROADMAP.md).

## Установка и сохранность данных

Установка берёт блокировку обслуживания, получает авторитетный простой runtime,
делает парную копию базы и изменяемых сессий. Помощник ждёт завершения приложения,
проверяет подготовленный артефакт и применяет его механизмом ОС. При отказе
сохраняются диагностические данные и возможность согласованного отката.
Секреты не входят в UI/логи; подписи, ownership и identity не обходятся.
[Восстановление](DATA-RECOVERY.md) · [Платформы](PLATFORMS.md).

Закрытие окна скрывает приложение в трей и оставляет агентов работающими.
Полный выход и установка используют штатный lifecycle. Старые сборки очищаются
только после проверки новой; чужие процессы, CLI, базы и резервные копии не удаляются.

## Выпуск

```sh
npm run release:local -- stable
# либо preview
```

Команда выполняет [канонические проверки](VERIFICATION.md), затем публикует
один проверенный commit через локального оператора или ключ подключённого устройства.
Изолированный signer Hub хранит приватный ключ; его не копируют в CI или на клиенты.
Права устройства, native fingerprint, версии, безопасные пути и CAS канала
проверяются повторно перед публикацией. Загруженный код на Hub не выполняется.
[Мастерская и авторизация выпуска](SELF-DEVELOPMENT.md).

Постоянное поручение владельца (31.10.2026): после принятой квитанции Мастерская
принимает обновление сама, без ручных кликов — через `desktop_updates`
([AGENT-CONTROL.md](AGENT-CONTROL.md)): `prepare`, опрос `status` до готовности,
`apply` последним действием. Hot-обновление перезагружает интерфейс; source-
обновление перезапускает приложение только после авторитетного простоя агентов,
сохраняя черновики, очереди и журнал доставки. Перезапуск после установки не
выглядит падением: штатная квитанция `last-install.json` несёт `ts`, и первый
запуск после свежей подтверждённой установки показывает, какая версия применена
и что данные сохранены (устаревшая, будущая или receipt без `ts` молчат —
старое обновление не объявляется заново). Явный запрет владельца или
недоступный инструмент оставляют обычное предложение обновления.

Порядокtracked-изменений вокруг публикации закреплён в publisher'ах: Hub
хранит `publication.commit` выпустившего коммита, и квитанция обязана ему
соответствовать. Финальные tracked заметки и checkpoint — до `release:local`;
операционные итоги после публикации — в `.local`. После проверки квитанции,
served head и publication.commit пушится тот же HEAD в main, и `release:packages`
диспатчится до любых новых tracked-коммитов: CI собирает пакеты только при
`published_commit == github.sha`, а повторный publish с изменившегося HEAD
отказывается, не трогая immutable-выпуск.

Проверьте `.local/releases/<version>-<channel>.json`, served head и подписи обоих
пакетов с фактическими файлами этого commit. Upload без этих проверок не является
доказательством доступности обновления. GitHub-публикация использует тот же commit. После появления этого commit в main:

```sh
npm run release:packages -- stable
```

Команда требует квитанцию проверенной публикации Hub и совпадение с GitHub main,
затем запускает workflow с `published_commit`. Обычные push/PR только проверяют
и собирают; они не публикуют установщики. После успешных заданий всех трёх ОС
workflow создаёт draft, загружает пакеты и `enki-native.json`, затем открывает
релиз. Существующую версию не заменяет. Hub выдаёт пакет лишь после успешного
завершения workflow; во время сборки доступна явная локальная сборка.
Публикация пакетов требует прав репозитория GitHub; ключ устройства Hub этих прав
не предоставляет. На устройстве без этих прав исходники можно публиковать через
Hub, а пакетный workflow запускает оператор репозитория.

## Ручная загрузка исходников

Hub предоставляет LAN HTTPS-маршруты:

- `/downloads/latest` — версия, размер, SHA256 и неизменяемая ссылка.
- `/downloads/latest/source.zip` — stable-исходники.
- `/downloads/source/{payloadSha256}.zip` — конкретный снимок.
- `/downloads/source/{payloadSha256}.json` — оригинальный подписанный пакет.

Маршруты не открывают приватные API Hub. Проверяйте TLS по доверенному сертификату,
затем размер/hash; обычный ZIP не заменяет оригинальную подпись updater-пакета.
[Windows](WINDOWS-BOOTSTRAP.md). Preview не подменяет stable.

## Сервер

Контракт и хранение реализованы в `services/hub/releases.py`,
`device_updates.py`, `native_updates.py`, `release_signer.py`; клиент — `src-tauri/src/hub_updates`.
[Операторская инструкция](../services/hub/README.md). Не изменяйте неизменяемый
пакет под тем же digest/версией. Совместимые маршруты читают старые клиенты, но
они не являются самостоятельным исполняющим ядром Enki.

Локальная компиляция использует [ограниченный кэш на Hub](BUILD-CACHE.md).
