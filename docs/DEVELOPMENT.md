# Разработка Enki

## Подготовка

Локальные Node и GitHub CLI можно установить в ignored `.local/tools`:

```sh
npm run dev:setup
npm run dev:run -- npm test
npm run dev:run -- npm run build:macos
npm run dev:run -- npm run release:local -- stable
npm run dev:run -- npm run release:packages -- stable
```

Node берётся из существующего runtime lock, GitHub CLI — из
`scripts/dev-tools.json`; архивы проверяются по SHA256 до распаковки. Wrapper
проверяет хеши executable, задаёт heap768MiB и Cargo jobs2, отдельные npm cache/
config, Cargo cache и GH_CONFIG_DIR. NODE_PATH другого проекта исключается.
Системные CLI, shell profiles и настройки моделей не меняются. Rust/Cargo и
системный SDK остаются установленными предпосылками; их версии выводятся setup.
На этом Mac ими уже собрана нативная Enki. Windows/Linux пакеты требуют своей
ОС и SDK либо штатного GitHub Actions workflow, а не macOS cross-build.

Доступ к GitHub Actions настраивается отдельно:
`npm run dev:run -- gh auth login --hostname github.com --web --git-protocol https`.
Это обычное подтверждение владельцем в GitHub; ключ Hub его не заменяет.
Credential/config не входят в исходники и пакеты. Git remote/credential helper
автоматически не меняются. Установка инструментов сама по себе ничего не публикует.

Используйте проверенные lockfiles, Node из `scripts/runtime/sdk-contract.mjs`,
Rust/Cargo и системные зависимости [своей платформы](PLATFORMS.md).
Если окружение задаёт `NODE_PATH` из другого проекта, исключите его из запуска.

```sh
npm ci
npm ci --prefix src-tauri/resources/agent --ignore-scripts
npm rebuild --prefix src-tauri/resources/agent node-pty
npm --prefix src-tauri/resources/agent run typecheck
npm run sdk:check
```

`npm run dev` запускает только интерфейс Vite. Нативная сборка:
`npm run build:macos`, `npm.cmd run build:windows` или `npm run build:linux`.
Эти команды готовят подписанный манифест встроенного runtime и упаковывают его
с приложением; отдельно установленный агентский CLI не используется.
`npm run tauri -- build …` также проходит подготовку runtime.

## Изоляция

Для нативной приёмки задайте `ENKI_PROFILE_DIR` новым абсолютным каталогом.
Перед отправкой запроса подтвердите изоляцию WebView, runtime и ключей.
Тестовые репозитории, файлы и чаты создавайте отдельно. Не очищайте существующую
историю для теста, не переключайте GPU и не запускайте параллельные модельные
пробы без явного поручения. Управляйте только процессами, созданными проверкой.

## Цикл изменения

1. Прочитайте `AGENTS.md`, краткую `.pi/TASK.md` и относящиеся к задаче исходники.
2. Зафиксируйте ожидаемое поведение и существенный сценарий ошибки.
3. Исправьте общий контракт, добавьте содержательную регрессию там, где она нужна.
4. Выполните профильные проверки; перед выпуском — [полные обязательные проверки](VERIFICATION.md).
5. Проверьте diff и реальный интерфейс, если меняли пользовательский сценарий.
6. Обновите действующую документацию. В checkpoint оставьте только текущую задачу,
   проверенные факты, незакрытые пункты и следующий шаг.

Cargo запускайте с `CARGO_BUILD_JOBS=2` или меньше. Первый прогон зависимостей
может быть долгим: используйте ограниченный, но достаточный срок и сохраняйте
код завершения. Не маскируйте неуспешную команду через `tail` или успешный wrapper.

## UI-проверка

Проверяйте светлую/тёмную тему, узкое окно, длинные названия, пустое состояние,
длинную историю, ошибки инструментов, ожидание ответа, клавиатуру и возврат
фокуса. Панели не должны размонтировать работающий чат или терять черновик.
Fixture IPC допустим только в явно проверочном интерфейсе; релиз использует
реальные реализации.

Порядок публикации и различие сборки/установки описаны в
[HUB-UPDATES](HUB-UPDATES.md). Приватные логи и квитанции не коммитьте.

## Временные файлы проверок

Общий runtime harness регистрирует только созданные им временные каталоги и
убирает их при выходе тестового worker. `harness.stop()` сохраняет файлы для
restart/recovery сценариев в той же проверке. Принудительное завершение процесса
может обойти exit-hook; такие остатки не являются пользовательскими сессиями.
Vitest и отдельные SDK Node-suite процессы ограничены heap в 1024 МиБ.
При разработке через Enki временные файлы инструментов находятся в `tmp`
выбранного [хранилища приложения](DATA-RECOVERY.md).
