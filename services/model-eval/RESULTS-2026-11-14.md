# Final model comparison — 2026-11-14

Six synthetic engineering tasks, the same prompts and offline tests for
`qwen38-flash-next` (Strata 0.1.59) and `ornith15-122b` (Infernix NVFP4,
24 CPU workers, MTP 3). Temperature 0, one active model at a time, generated
code compiled/tested in isolated task folders. Harness: `run.py`/`verify.py`.

## Automated result

| Task | Qwen3.8 | Ornith Infernix | What was checked |
| --- | --- | --- | --- |
| Python token bucket | PASS | PASS | finite/positive arguments, clock rollback, capacity/refill, locking |
| JS telemetry | PASS | PASS | plain object, bounds, NaN/Infinity, CSV escaping |
| 3D module | PASS | PASS | cuboid extents, perspective defaults, painter-sorted faces |
| ESP32 controller | PASS | PASS | C++17 compile, LED, sensor timing, debounce, no delay |
| Bug repair | PASS | PASS | LRU eviction/recency, update, invalid capacity |
| Scheduling | PASS | PASS | valid 3-server assignment, exact optimum `9,9,9` |
| **Score** | **6/6** | **6/6** | narrow automated contract |

The previous 3D failures were caused by an ambiguous default-width contract and
an Ornith face-index bug; after clarifying the contract both models pass. The
earlier ESP32 false negatives were test-stub omissions, not model errors. No
generated code was patched to pass.

## Conclusion

On these six engineering tasks **no quality winner can be declared**: both pass
all automated assertions. Qwen generates substantially faster and is the better
default for normal coding/backend/frontend/ESP32 work. Infernix/Ornith is the
right choice for 262K long-context work and remains available when Qwen fails
or the task needs the NVFP4 checkpoint; it has not demonstrated superior code
quality here.

This is a bounded synthetic suite, not a general intelligence score. It does not
measure visual design quality, unseen reasoning, long-session agent reliability,
or human preference. Do not conclude that either model is universally “smarter”
from six tasks.
