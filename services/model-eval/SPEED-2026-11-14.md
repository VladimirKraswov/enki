# Maximum decode speed — 2026-11-14

Both models ran on the same dedicated host NUMA node 0: VM 5200 with 236 GiB
allocated (231 GiB visible) and 40 hardware threads. Infernix used 24 CPU
expert workers; Qwen's Strata pool used 32 workers. Only one model was active
at a time. `enable_thinking=false`, temperature 0, no tools.

The harness is `services/model-eval/speed.py`. Figures are engine timings, not
wall-clock estimates. "Max" is the best single request in this run; the median
is the honest sustained figure.

## Short prompts (512 generated tokens)

| Model | Run 1 | Run 2 | Run 3 | Median | Max |
| --- | ---: | ---: | ---: | ---: | ---: |
| Qwen3.8-Flash-Next | 101.1 | 110.6 | 99.1 | **101.1** | **110.6 tok/s** |
| Ornith-1.5-122B NVFP4 | 46.8 | 54.9 | 63.6 | **54.9** | **63.6 tok/s** |

Each run generated exactly 512 completion tokens. Ornith's speed rose as its
expert cache warmed; the third run was the maximum observed. This is not a
cherry-picked instantaneous burst.

## Longer context

| Model | Actual prompt | Completion | Prefill | Decode |
| --- | ---: | ---: | ---: | ---: |
| Qwen | 6,472 tok | 151 | 1,332 tok/s | 77.3 tok/s |
| Ornith | 6,432 tok | 92 | 1,801 tok/s | 45.8 tok/s |
| Qwen | 52,072 tok | 128 | 4,223 tok/s | **115.3 tok/s** |
| Ornith | 52,032 tok | 113 | 3,984 tok/s | 52.1 tok/s |

The "65K" prompt produced about 52K tokens with this tokenizer. Qwen's fastest
observed decode in the whole test was **115.3 tok/s** at 52K context; Ornith's
fastest was **63.6 tok/s** on a warmed short prompt.

## Answers

- Qwen maximum observed: **115.3 tok/s** (52K context); short median 101.1.
- Ornith maximum observed: **63.6 tok/s** (warm short context); short median 54.9.
- Infernix has faster long-prompt prefill at the ~6K test (1,801 vs 1,332
  tok/s); at ~52K Qwen is slightly faster in prefill and much faster in decode.

No quality shortcuts were enabled: this is the normal MTP/Strata configuration
with thinking disabled only for a like-for-like speed measurement.
