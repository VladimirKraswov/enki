# Strata на RTX 5090

Операторские шаблоны для отдельного сервиса модели, не встроенный движок Enki.
Профиль проверен на VM 5200: RTX 5090 32 ГБ, Xeon E5-2698 v4, DDR4,
PCIe 3.0 ×16, 32 vCPU и около 157 ГиБ RAM. V100 и его gateway независимы.

```text
Enki Runtime / Hub                  → VM 192.168.31.71:1919
Операторский loopback-туннель :18019  → VM 127.0.0.1:1919
                                      nginx, только API модели
                                      → Strata 127.0.0.1:1920
```

Сохранены ID `qwen38-flash-next`, URL и ключ совместимости LAN-клиентов.
Этот старый ключ — публичная заглушка, а не защита для размещения в интернете.
Внутренний Strata использует отдельный случайный ключ; Hub имеет собственный
закрытый ключ шлюза. Страницы настроек, загрузка/выгрузка и остальные служебные
маршруты наружу не проксируются. Проксирование не повторяет POST, не буферизует
SSE и передаёт отключение клиента серверу. Стандартная nginx.service отключена;
работает отдельная strata-gateway.service, без сайта/порта 80.

## Установленные компоненты

| Путь / служба | Назначение |
| --- | --- |
| `/opt/strata/bin` | Собранные под sm_120 движок и GPU Vision |
| `/opt/strata/app` | Python-сервер из закреплённого Strata checkout |
| `/opt/strata/venv` | Самостоятельная среда; Torch и FreeToken не нужны |
| `/opt/strata/ops` | Проверка готовности и ограниченный watchdog |
| `/srv/models/qwen38-flash-next-strata` | Подготовленные веса, tokenizer, PLE, MTP, mmproj |
| `/etc/strata/model.json` | Фактический профиль без секретов |
| `/etc/strata/api.env` | Закрытый ключ внутреннего API |
| `/etc/strata/gateway-secrets.json`, `gateway.conf` | Частные данные/конфигурация шлюза; не публиковать |
| `strata-api.service` | Один выполняемый запрос и FIFO; отдельный пользователь, readonly-система |
| `strata-gateway.service` | Совместимые явные LAN/loopback listeners на 1919 |
| `strata-watchdog.timer` | HTTP/process liveness без inference и повторной отправки промптов |

Watchdog ждёт три подтверждённых сбоя, выдерживает минимум 10 минут между
восстановлениями и ограничен тремя за час. systemd также ограничивает повторные
старты. Во время загрузки служба остаётся activating; Hub открывает gate только
после правдивого health и точного model ID. Приватный `/dev/shm` этой службы
содержит arena экспертов и освобождается при остановке. CUDA/NVIDIA и общий
nvidia-power-limit.service сохраняются отдельно от движка.

## Проверенный профиль

Strata `f57c0adcb31c00f3f216550c004dac4e713a9f70`, engine 0.1.45.3;
llama.cpp для Vision `3cf03257f219afbe7334045ff7c6a06ac68c627d`.
Источник — OrcaRouter-Qwen3.8-Flash-Next-Uncensored-ModelOpt-NVFP4,
revision `f24d2b68ff2814f24455ae86717be276619b5664`.

Нативное окно 262144, INT8 KV, GPU Vision до 4096 image-токенов, исходные NVFP4
эксперты и FP8 PLE, Q8 плотные веса (малые тензоры BF16/F32). MTP6,
spec-min-p 0.70, pcie-frac 0.16, prefill auto:32768, vram-reserve-mib 1500,
expert-cache auto, PLE в RAM, STRATA_ROUTE_TAIL_SKIP=0,
STRATA_PREFILL_NVFP4=w4a8. При temperature 1: top-k 20 / top-p 0.95.
Дополнительные Q4 draft, async-cache и резерв 700 не выбраны по результатам
замеров; последний оставлял лишь около 268 МиБ VRAM. Итоговый профиль оставлял
около 1 ГиБ. Окно включает вход и выход; клиентский резерв ответа/автосжатия
не равен физическому пределу движка.

В последовательном HTTP/SSE сравнении при temperature 1 и 768 выходных токенах:
прежняя FreeToken-конфигурация — 33–35 токенов/с против Strata 82–86 на коротком
вводе. На 249K токенов разнообразного исходного кода — 32.6 против 80–93 токенов/с,
TTFT 97 против 50–52 с. Через итоговый рабочий шлюз: 82–85 на коротком вводе,
80 на длинном; верхние значения диапазонов получены в пилотном прогоне.
Разброс зависит от текста/маршрутизации/MTP; это не гарантия скорости каждого
ответа. Проверены 12 задач JSON/инструментов/длинного контекста/Vision и 6 задач
кода с 20 поведенческими проверками. Это ограниченная проверка качества,
не доказательство полного равенства всех ответов после квантования.

FreeToken удалён из VM после приёмки. Проверена настоящая перезагрузка VM:
автозапуск всех трёх служб, восстановление прежнего SSH-туннеля, реальные
OpenCode/Pi read-tool turns на Medium и новый Vision-запрос. Старт до готовности
занял около 108 с. Исходный HF-чекпойнт сохранён как данные модели; зависимостей
от старого движка нет. Проверка Windows/Linux GUI отдельно не проводилась.

## Проверка и обновление

```sh
python3 -m unittest discover -s services/strata -p 'test_*.py'
python3 -m unittest discover -s services/hub/tests
ssh vm-5200 'systemctl is-active strata-api strata-gateway strata-watchdog.timer'
curl -fsS http://127.0.0.1:18019/health
curl -fsS -H 'Authorization: Bearer local' http://127.0.0.1:18019/v1/models
```

Живой nginx-тест запускает только временные loopback-порты и HTTP-заглушку,
без GPU/промптов/секретов. На машине без nginx он явно пропускается.
При изменениях runtime/profile оператор сначала проверяет независимые
зависимости, native/vision binaries, готовность, реальный Enki tool turn,
отмену и длинный ввод. Не запускайте два движка на одной GPU. Не используйте
историю владельца как тест и не повторяйте промпт после неоднозначного timeout.
Настройки клиентов публикуются через аутентифицированный CAS каталога Hub;
операторские ключи остаются вне Git и клиентского каталога.
