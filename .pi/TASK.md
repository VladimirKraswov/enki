## Срез 3 (2.0.109: канал заняли 2.0.107/2.0.108): большие транскрипты — ошибка «неверный тип или слишком велика»

Владелец прислал скриншот: «Не удалось подтвердить сохранение истории: История Pi
имеет неверный тип или слишком велика» и рядом «bash — выполнение не подтверждено
сервером».

Причина: после каждой пачки добавленных записей воркер перечитывал ВЕСЬ файл
транскрипта (`openSessionReader(...).all()`), чтобы подтвердить, что записи уже на
диске, и записать их в ledger команд. На файле больше 128 МБ это падало с общей
ошибкой, а на десятках мегабайт — просто жгло CPU и задерживало ход; из-за
неподтверждённой записи UI помечал вызов инструмента как «выполнение не
подтверждено сервером». Рядом та же беда в листинге каталога: `listSessionFiles`
читал каждый файл целиком и молча пропускал (`catch continue`) тот, что не
прочитался — большой чат исчезал из списка.

Сделано: `src/sessions/tail-scan.ts` (чтение хвоста/начала файла с бюджетом,
подтверждение id по хвосту, отказ на не-файл и на повреждённую строку); воркер
подтверждает сохранение по хвосту с одним полным чтением как резервом; листинг
больших файлов берёт заголовок + начало (название) + хвост (валидность); общая
ошибка заменена на явные причины с размером файла.

Проверки: agent-пакет 517 PASS, включая `test/transcript-tail.test.ts` (6 тестов:
подтверждение по хвосту, поиск более старой записи увеличением бюджета,
повреждённая строка, оборванная запись записи, чтение заголовка/начала, отказ на
каталог).

Публикация: 2.0.106 получила 409 — канал уже содержал 2.0.108 от другого
устройства (66b9db46), поэтому тот же срез выпущен как 2.0.109.

## Срез 4 (2.0.110): чат 129 МБ снова открывается

После 2.0.109 отказ стал честным («слишком велика (129 МБ)»), но чат оставался
мёртвым: страница истории и ветвление читали файл целиком → HTTP 500, уточнения
не сопоставлялись с историей.

Сделано: `openReadableSessionReader` — для файлов больше 8 МБ берёт заголовок и
хвостовое окно (24 МБ), строит непрерывную цепочку parentId и отдаёт её как
branch; старые записи на диске не трогаются. Используется в `historyPage`,
в ветвлении (`branchSessionFile`), и в восстановлении прерванных инструментов
(там же убрано полное чтение файла — сканируется хвост).

Проверки: `test/transcript-bounded-reader.test.ts` (3 теста: окно 48 МБ → ветка
непрерывна, новейшая запись есть, m0 не загружен; маленький файл читается точно;
повреждённый заголовок отклоняется), agent-пакет 524 PASS.
